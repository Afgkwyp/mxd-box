# 现有功能盘点 + 新功能候选清单

> 盘点基于 `main` 分支 0.2.0（提交 `1cc9ddb`）的实际代码，写于 2026-10-10。
> 本文只出方案，不改功能代码。挑中的候选项会另写可直接开发的详细方案。

## 怎么读这份文档

- **第一部分**是现状：现在有什么、入口在哪个文件。
- **第二部分**是候选：15 项新功能，先看 2.1 的总表和优先级，感兴趣的再看 2.3 的逐项说明。
- **第三部分**是需要你回答的问题，其中 3 个会直接改变优先级。
- **第四部分**是通读时顺带发现的问题，本次不修。

工作量档位是粗估，按「一个熟悉本仓库的开发者」算：**S** = 1 天以内，**M** = 2–4 天，**L** = 1 周以上。

### 2.2 取舍依据

候选的数量和方向任务里没有限定，我按下面四条筛的：

1. **优先补「已经做了一半」的**。1、9、14 的后端和数据都在，只差界面；2 是把两个已有功能接起来。这类投入小、风险低。
2. **优先解决「人不盯着工具时」的场景**。这个工具自己的开发笔记里写过：大半价值发生在主窗口不在前台的时候。4、5、6、11 都是把「要人去看」变成「到时候叫你」，并且全部复用现成的提醒出口（`alert.rs`）。
3. **把能解锁欠账的排前面**。`docs/TODO.md` 里的问题几乎都卡在同一件事上——没有别的分辨率下的真机画面。3 不是面向玩家的功能，但它决定经验统计这个核心功能在别人机器上能不能修好。
4. **不越过项目自己的边界**。不读游戏内存、不注入、不模拟按键；不给小册子增加明显的请求压力（它是第三方站点，项目里已经为此做了缓存和防连点）；保持单 exe 便携。

**我考虑过但不建议做的**：

| 想法 | 不建议的原因 |
| --- | --- |
| 金币 / 掉落收益统计（每小时赚多少金币） | 金币数只在背包打开时显示在画面上，截屏读不到常驻数字；要做就得让玩家一直开着背包。可行性待确认，不建议现在投入 |
| 击杀数 / 每小时击杀估算 | 掉落接口里有怪物经验值，理论上可以用「经验增量 ÷ 单只经验」反推，但经验倍率、组队分成、同图多种怪都会让结果失真。这些机制的具体数值我不确定，标为待确认；在弄清之前给出的数字不可信 |
| 自动更新（下载后自动替换 exe） | 开发笔记里已有明确结论：未签名便携版做自动替换，失败模式是「朋友的程序坏了」。维持现状 |
| 内置 BOSS 刷新时间、任务攻略、升级路线等资料库 | 需要大量游戏数据，我无法保证准确，也没有可核对的来源。候选 11 用「用户自己填时间」绕开了这个问题 |

### 2.3 逐项说明

#### 1. 提醒历史 —— P0，S

- **价值**：开服提醒、金价到价、黑名单命中的弹窗 20 秒就自动关。人不在电脑前就错过了，回来没有任何地方能查「刚才是不是响过」「几点开的服」。
- **做法**：数据已经在写（`alert.rs` 的 `record_alert_history` → `alert_history` 表，字段是类型、标题、详情、时间），命令 `list_alert_history` / `clear_alert_history` 也已注册。只需要在「提醒」页加一张「最近提醒」卡片：按时间倒序列出，带类型图标，一个清空按钮。总览页的「提醒」小卡片可以顺带显示最近一条。
- **风险 / 依赖**：几乎没有。`alert_history` 表现在只有插入和整表清空（`db.rs` 的 `record_alert` / `clear_alert_history`），没有条数上限，做的时候加一个「只保留最近 N 条」。

#### 2. 掉落 ⇄ 查价联动 —— P0，S

- **价值**：典型路径是「这只怪掉什么 → 这东西现在卖多少钱」以及反过来「这东西很贵 → 哪只怪掉」。现在两边的结果互不相通（`MobDrops.tsx` 里没有查价入口，`MarketSearch.tsx` / `ItemDetailPanel.tsx` 里没有查掉落入口），玩家要切页签重新打一遍物品名。
- **做法**：
  - 掉落结果里每个道具加一个「查价」小按钮，带着道具名跳到物价页签并直接查。主窗口已有现成机制（总览「最近查价」用的 `MarketSeed`），查价窗里是切 `mode` 并填输入框。
  - 物价结果的详情栏加一个「谁掉」按钮，带着道具名或道具 ID 跳到掉落页签。
- **风险 / 依赖**：拍卖查询按关键词模糊匹配，同名或名字互相包含的道具会多出结果，属于可接受范围。两个方向都受现有冷却约束（查询类 5 秒），连续点会被拦，需要让提示说清楚。

#### 3. 一键导出诊断包 —— P0，M

- **价值**：面向的是「报问题的群友」和开发者。`docs/TODO.md` 的 7 条欠账里，紧凑版状态栏角色识别、小分辨率认错首字、2K/4K 未实测、地图名只在 1080p 验过、4K 缩放下经验行，这些都写着同一句话：要真机画面。现在取样要让对方跑 `cargo test` 探针，普通玩家做不到。
- **做法**：在「设置 → 通用」或「练级」页读不到时的失败横幅里加「导出诊断包」。点一下把以下内容打成一个 zip 放到桌面并在资源管理器里选中（落盘和选中的写法可参考 `save_share_card` / `download_update`）：
  - 当前游戏窗口的一整帧截图（`exp/capture.rs` 已能抓）；
  - 客户区尺寸、显示缩放、HUD 定位结果、读取链每一步的结论（`get_exp_preview` 这类现成的诊断信息可以复用，具体内容待开发时核对）；
  - 日志文件和已有的 `logs\经验样本\`。
- **风险 / 依赖**：
  - **隐私**：整帧截图里有角色名、聊天内容、可能还有好友列表。必须在导出前明确告知包里有什么，只存本地、不自动上传，由用户自己决定发不发。
  - zip 打包需要引入一个纯 Rust 的压缩库，或者退而求其次只导出一个文件夹（不加依赖，更稳）。建议先做文件夹版。
  - 游戏没开或最小化时抓不到帧，要给明确提示而不是导出一个空包。

#### 4. 内存到线提醒 —— P0，S

- **价值**：内存监控是这个工具最早的功能之一，但超线之后只是侧栏和悬浮窗上的数字变红（`memory.rs` 只发 `memory-update` 事件，没有接提醒出口）。打游戏时看不到侧栏，等发现时往往已经卡了。
- **做法**：`alert.rs` 加一个内存来源，沿用响铃 + 闪任务栏 + 右下角弹窗。触发规则照金价提醒的写法（`meso_alert.rs` 的「跨过去才响，回落后才重新上膛」）：占用从线下升到线上并持续一小段时间才响一次，回落到线下若干个百分点后才允许再响，外加一个较长的冷却。设置里给一个开关，默认值待定（见第三部分问题 6）。
- **风险 / 依赖**：误报是主要风险——内存在警戒线附近抖动会反复触发，所以回落幅度和持续时间必须有。界面上现有的那句「建议进商城刷新」是项目作者写的经验之谈，其机制我没有依据核实，提醒文案沿用原话即可，不扩写。

#### 5. 挂机守护：掉线 / 经验停涨 / 升级提醒 —— P1，M

- **价值**：挂机练级时最怕两件事：掉线了不知道，角色死了不知道。两种情况都是白挂几十分钟。工具其实已经能感知到：
  - 掉线：`channel.rs` 能看到游戏连接断开，并且已经在区分「断线后才到别的线」；
  - 停涨：`tracker.rs` 有 `idle_secs`，界面上已经在显示「未涨经验」；
  - 死亡掉经验：`table.rs` 的 `Advance::Loss` 已经能识别；
  - 升级：`level_ups` 已有。
- **做法**：只在「经验统计进行中」时生效（没开统计的时候不打扰）。三类事件各一个开关：
  - 连接断开超过 N 秒 → 提醒「游戏连接断了」；
  - 连续 N 分钟没涨经验 → 提醒「经验停了」，N 由用户设；
  - 升级 / 达到练级目标 → 提醒（这个偏正向，可以默认用更轻的提示）。
  全部走 `alert.rs`，各自独立冷却。
- **风险 / 依赖**：
  - 开发笔记里明确写了：**分不清掉线和主动下线**，换线卡顿超过 6 秒也会被记成断开。所以必须限定在统计进行中，并且阈值要比 6 秒长，否则每次换线都响。
  - 「经验停了」在正常玩法里也会发生（跑图、等人、清包），默认阈值宜长不宜短，并且同一次停涨只响一次。
  - 死亡单独提醒的可靠性待确认：一帧的经验减少也可能来自别的原因，我不确定游戏里除了死亡还有什么会扣经验，建议先只做「停涨」，死亡作为它的一个附加说明。

#### 6. 物品关注清单 + 到价提醒 —— P1，M–L，有前置问题

- **价值**：盯一件装备或卷轴的玩家，现在只能隔一会儿手动查一次。金价已经有到价提醒，物品没有。
- **做法**：物价结果上加「关注」；关注清单保存物品名、区服、目标价；后台定时用现有的 `query_market` 逻辑查最低价，跌到目标价以下提醒一次（规则照 `meso_alert.rs`）。清单页同时充当「常查物品」的快捷入口，顺带可以把每次查到的最低价存下来，积累出自己的价格走势。
- **风险 / 依赖**：
  - **0.1.4 的更新说明写着「删掉了关注清单」**。当初为什么删，仓库里读不出来。在弄清原因之前不建议动工（见第三部分问题 3）。
  - **对小册子的请求压力**：拍卖查询每次要抓一张约 180KB 的页面，还依赖查询凭证，站点有限流。必须限制清单条数（例如 10 条以内）、拉长间隔（例如每条 15–30 分钟）、并且错开请求。这是 L 档的主要来源。
  - 拍卖查询是否需要登录凭证才稳定，我没有完全读清，待开发时核对；如果需要，未登录用户要有明确提示。
  - 结果里只有「最低价」一个数，没有数量和卖家，到价提醒只能按最低价判断。

#### 7. 数据备份与恢复 —— P1，S–M

- **价值**：设置、黑名单、练级历史、角色列表、校准位置全在本机一个 SQLite 文件里。换电脑、重装系统就没了。练级历史是玩家攒了很久的东西，丢了补不回来。
- **做法**：「设置 → 通用」加「导出备份」和「从备份恢复」。导出就是把数据库文件一致性地复制一份到用户选的位置（SQLite 有在线备份接口，避免复制到写了一半的文件）；恢复是校验文件后替换并重启。
- **风险 / 依赖**：
  - 数据库里有小册子登录凭证（`auth_cookie`）。导出的备份里**不应带凭证**，否则用户把备份发给别人等于交出登录态。导出时要清掉这一项。
  - 悬浮窗尺寸、查价历史、角色形象等存在 WebView 的 localStorage 里，不在数据库中，第一版不备份这些，要在界面上说清楚。
  - 恢复是覆盖操作，必须有确认，并且恢复前自动把当前库另存一份。
  - 校准位置是比例坐标，换电脑后一般仍然可用；线号的手动校准按节点地址记，也能带走。

#### 8. 练级日报 / 周报 —— P1，M

- **价值**：历史是一段一段的会话，看得到单次时速，看不到「今天一共练了多久、涨了多少」「这周比上周如何」。对坚持练级的玩家，这是最直接的正反馈。
- **做法**：`exp_sessions` 里已有开始时间、有效时长、净经验、起止等级，按自然日 / 周聚合即可，不需要新采集。练级页历史区上方加一个「按天 / 按周」的柱状图和一行汇总（时长、经验、升了几级、平均时速），沿用按角色筛选。
- **风险 / 依赖**：
  - `exp/report.rs` 的文档明确写了老记录的 `ended_at` 不可信，时长只能用 `active_secs`；跨零点的会话归到哪一天要定一条规则（建议按开始时间）。
  - 「不建议用于比较」的会话是否计入日汇总要定口径：建议经验和时长照算（那是真实发生的），但平均时速不纳入。
  - 新图表要照现有约定按主题取颜色（Recharts 不认 CSS 变量）。

#### 9. 地图效率榜 —— P1，S–M，有前置问题

- **价值**：回答「我在哪张图练得最快」。地图名现在是自动识别的，数据会自然积累。
- **做法**：后端 `exp_report` 已经能给出每张地图的会话数、累计时长、平均时速、最佳时速，以及每段相对同图均值的差值，带单测。前端加一张按时速排序的表即可。
- **风险 / 依赖**：
  - **0.1.4 明确删过这块界面**，原因未知（见第三部分问题 3）。有可能是当时地图名靠手填、数据太脏；现在地图名自动识别，情况可能已经不同，但这只是我的推测。
  - 同一张图在不同等级时速差别很大，直接排名会误导。建议至少按角色筛选，并在每行标出等级区间。
  - 地图名认错或历史里有旧的错名时会拆成两行，需要一个合并 / 改名入口，否则榜单会越来越乱。

#### 10. 角色合并 —— P1，S–M

- **价值**：`docs/TODO.md` 第 4 条：同一个号在小分辨率下可能被认成另一个角色，现在只能移除其中一个，它的历史变成「没有归属」。0.2.0 刚把历史按角色分开，这个问题会随着用的人变多而出现。
- **做法**：角色列表里加「合并到…」：把源角色名下的会话和识别指纹（`exp_character_marks`）改挂到目标角色，再删掉源角色。指纹一并迁移后，以后在那个分辨率下也会直接认成目标角色。
- **风险 / 依赖**：合并不可逆，要有确认框写清后果。当前登录中的角色被合并时的处理要想清楚（建议统计进行中禁止合并）。

#### 11. 自定义计时提醒 —— P2，M

- **价值**：游戏里有不少要掐时间的事，玩家现在用手机闹钟或者干脆忘了。
- **做法**：一个通用的倒计时 / 定点提醒列表：用户自己起名字、自己填时长或时刻，可以设为循环，到点走 `alert.rs`。经验窗或查价窗上可以显示最近一个倒计时。再给几个全局快捷键位「一键重新开始某个计时」，这样在游戏里不用切窗口。
- **风险 / 依赖**：
  - **不内置任何游戏数值**（BOSS 刷新间隔、增益持续时间等）。这些数据我不确定，怀旧服的具体设定也待确认，所以全部由用户自己填。
  - 全局快捷键会把按键从游戏手里抢走，开发笔记里已经踩过这个坑，默认值必须是组合键。
  - 和工具现有定位（查价、练级、提醒）相比稍微发散，所以排在 P2。

#### 12. 多区服 / 多条件金价提醒 —— P2，S

- **价值**：现在金价提醒只盯预设区服，「涨到」「跌到」各一个数。同时关心几个区服的人只能来回切预设区服，而切服会清掉已触发状态。
- **做法**：把 `MesoAlertConfig` 从一组阈值扩成按区服的列表，判定函数 `decide` 不变，状态键已经带区服号。金价数据一次请求就包含所有区服，不增加对站点的请求。
- **风险 / 依赖**：设置的存储格式要兼容老配置。需求强度不确定，取决于有多少玩家同时关注多个区服（见第三部分问题 2）。

#### 13. 新手首次引导 —— P2，M

- **价值**：新用户第一次打开看到的是「这一版更新了什么」弹窗，内容是版本变化而不是怎么用。两个悬浮窗的快捷键、经验统计要点「开始」、关窗其实是收进托盘，这些都要自己摸索。
- **做法**：首次启动（没有 `last_seen_version` 记录）时换成一个 3–4 步的引导：选区服 → 试一下 `Alt+F` → 试一下 `F10` → 说明关窗会收进托盘。之后的版本升级仍然弹更新说明。「关于」页留一个「再看一遍」入口。
- **风险 / 依赖**：项目有明确的界面文案约定——只留必要的功能文字，不写解释。引导必须短，能跳过，不能做成说明书。这一项偏体验优化，是否算「新功能」由你定。

#### 14. 黑名单导入导出 —— P2，代码 S，但需要先做决策

- **价值**：朋友、公会之间共享避坑名单。
- **做法**：后端命令和单测都在，恢复界面入口即可。
- **风险 / 依赖**：开发笔记里已经把问题说得很清楚——黑名单按名字比对，命中会响铃弹窗，一份别人给的名单可以直接毁掉一个人的风评。恢复之前要先定规则，我的建议是：**导入的记录单独标记来源，并且默认只在「查这个人」时显示，不触发剪贴板自动提醒**，用户逐条确认后才升级为会提醒的记录。这样共享的价值保留了，误伤的代价降下来。是否接受这个折中需要你定。

#### 15. 小结卡片扩展 —— P2，M

- **价值**：小结卡片是这个工具里最有传播性的功能（发群、发朋友圈，页脚带软件名）。现在只有「一段练级」一种卡。
- **做法**：复用 `shareCard.ts` 的画法，增加两种卡：
  - **日卡 / 周卡**：依赖候选 8 的聚合数据；
  - **升级卡**：升级那一刻生成，写从几级到几级、这一级用了多久。
- **风险 / 依赖**：依赖候选 8 先做。稀有度评级规则现在是按个人历史比出来的，新卡种要各自定一套，避免「随便练一下就 SSR」。属于锦上添花。

## 三、需要你回答的问题

前三个会直接影响优先级。

1. **目标玩家是谁？** 从功能看，现在同时照顾了练级党（经验统计）、商人（查价、金价）、交易安全（黑名单）。如果有侧重，候选的排序会不同：偏练级 → 5、8、9、10 提前；偏交易 → 6、12、14 提前。
2. **具体是哪个怀旧服、什么版本？** 仓库里能读出来的只有：区服是蓝蜗牛 / 蘑菇仔 / 绿水灵 / 漂漂猪 / 小白兔五个，每服 60 条线，经验表做到 120 级，文档里称「国服怀旧服」。版本号、职业范围、有没有后续开新服的计划都读不出来。这关系到 11 能不能内置预设、以及游戏机制类功能要不要投入。
3. **0.1.4 为什么删掉「关注清单」和「地图效率与历史对比」？** 是数据不准、界面太挤、对小册子压力大，还是没人用？这决定候选 6 和 9 是「可以重做」还是「不要再碰」。
4. **小册子那边的态度**。工具的数据几乎都来自它。候选 6 会明显增加请求量。有没有和站长沟通过、对方有没有频率上的要求？
5. **诊断包（候选 3）里带整帧截图，可以接受吗？** 还是只允许带 HUD 那一条（现在 `经验样本` 已经在存的范围）？只带一条的话，角色识别和地图名的问题仍然取不到样。
6. **内存提醒（候选 4）默认开还是默认关？** 默认开对新用户更有用，但老用户升级后会突然多一种响铃。
7. **发布形态会不会变？** 现在是未签名单 exe。如果以后出安装包，原生系统通知会自动生效（代码里已经留了），自动更新也可以重新评估。
