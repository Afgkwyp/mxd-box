# 方案：掉落 ⇄ 查价联动

> 状态：待开发。对应 `docs/FEATURE_CANDIDATES.md` 候选 2。
> 基于 `main` 分支 0.2.0 的代码写成，行号可能随后续提交变化，以函数名和组件名为准。

## 1. 要解决的问题

练级时最常见的两条查询路径，现在都要手动重打一遍物品名：

- **掉落 → 价格**：查到这只怪掉什么，想知道其中某件现在拍卖行卖多少。
- **价格 → 掉落**：查到某件东西很值钱，想知道哪只怪掉、掉率多少、在哪张图。

两边的查询能力都已经有了（`search_drops`、`query_market`），本方案只做「把结果接起来」，**不新增后端命令，不新增对小册子的请求类型**。

## 2. 范围

| 入口 | 掉落 → 查价 | 查价 → 掉落 |
| --- | --- | --- |
| 主窗口「查询」页 | 做 | 做 |
| 查价窗（`Alt+F`） | 做 | 做 |

不做：在掉落列表里直接内嵌显示价格（那样每展开一只怪就要发十几个拍卖请求，对小册子压力大，见第 6 节）。

## 3. 交互与界面

### 3.1 主窗口「查询」页

**掉落页签 → 物价页签**

- 每条掉落道具行右侧、概率数字左边，加一个小按钮「查价」（图标建议用现有的 `Tag` 或 `Coins`，带 `title="查这件的拍卖价"`）。
- 点击后：切到「物价」页签，搜索框填入道具名，立即发起查询。
- **任务道具不显示这个按钮**（`drop.questid > 0`）。道具名为空的行也不显示。
- 行本身现有的行为（点整行在小册子打开图鉴）保留。

**物价页签 → 掉落页签**

- 每张结果卡片底部现有的「详情」按钮旁边，加一个按钮「谁掉」（`title="查哪只怪掉这件"`）。
- 点击后：切到「掉落」页签，搜索框填入查询词，立即发起查询。
- 查询词用什么见 5.1。

**切页签不丢结果**

现在 `QueryPage` 是条件渲染，切走页签组件就卸载、结果清空。联动之后「看一眼价格再回来接着看掉落表」是主路径，回来发现列表没了、重查又被 5 秒冷却拦住，体验是断的。所以要把「物价」和「掉落」两个页签改成**保持挂载、只切显示**（「查人」页签可以维持现状）。

### 3.2 查价窗

查价窗是一根输入框 + 三个模式（`mode`），联动就是「换模式 + 填词 + 查」。

**掉落模式 → 查价模式**

- `HudDropRow` 每行右侧加一个紧凑的「价」按钮（任务道具不显示）。
- 点击：`mode` 切到 `price`，输入框填道具名，立即查价。

**查价模式 → 掉落模式**

- 右侧详情栏（`HudItemDetail`，窄窗时是行内展开的那块）加一个「谁掉」链接，样式用现有的 `tm-link`。
- 点击：`mode` 切到 `drop`，输入框填查询词，立即查掉落。

**切模式不丢结果**：查价窗里 `items` 和 `drops` 本来就是两份独立状态，切模式不会清，不用改。

### 3.3 文案

按项目的界面文案约定（只留动作，不写解释），新增的可见文字只有：`查价` / `价`、`谁掉`，以及两条悬停提示。不加说明段落。

## 4. 涉及的文件与改动点

只动前端，Rust 侧不改。

| 文件 | 改动 |

| `src/lib/changelog.ts` | 发版时加一条，例如「掉落结果里可以直接查这件的拍卖价，查价结果里可以直接看哪只怪掉」 |

**掉落行的结构调整（主窗口和查价窗都要做）**

现在整行是一个 `<button>`（点了去小册子）。按钮里不能再套按钮，所以要改成：外层换成 `<div>`，里面是「名称区按钮（保持原行为，占满剩余宽度）」+「查价按钮」+「概率」。改完要确认：行的高亮（命中的那条是绿色）、悬停效果、键盘 Tab 顺序都和原来一致。

## 5. 数据与边界情况

### 5.1 「谁掉」用道具 ID 还是道具名去查——需要先验证

- 拍卖结果的 `MarketItem.id` 是道具 ID（解析自结果卡片链接里的 `id=`，单测素材里是 `item.php?id=1092008`），掉落接口文档写明支持按道具 ID 查。
- **用 ID 查更准**：用名字查是模糊匹配，搜「锅盖」可能带出名字里含这两个字的别的东西。
- **但有一点我没有依据确认**：怪物 ID 和道具 ID 都是纯数字，掉落接口收到一个数字时怎么判断是哪一种、会不会两边都命中。

**开发第一步**：用现成的真实接口探针验证（`cargo test --lib probe_live_drops -- --ignored --nocapture`），拿几个已知道具 ID 去查，看结果是否只包含掉落这件道具的怪。

- 结果干净 → 用 ID 查。输入框里显示 ID 对玩家不友好，所以输入框填道具名，实际请求用 ID（`MobDrops` 的 seed 需要同时带「显示用的名字」和「实际查询词」）。
- 结果不干净或有歧义 → 退回用道具名查，实现更简单。

### 5.2 「查价」用道具名

拍卖查询只支持关键词，所以掉落 → 查价一律用 `drop.item.name`。已知影响：

- 名字是别的道具名的一部分时，结果会多出几条。可接受，玩家能自己认。
- 0 结果是正常情况（这件东西当前没人卖）。现有的空结果提示够用，不用为联动单独写文案。
- 现有规则「0 结果不写入最近查价」对联动同样生效，不用额外处理。

### 5.3 输入框的值不能靠 state 传

`setKeyword(x)` 之后立刻读 `keyword` 拿到的还是旧值。`MarketSearch.handleSearch` 和查价窗的 `handleSearch` 已经用 `override` 参数处理了这个问题；查价窗的 `handleSearchDrops` 还没有，这次要补上。否则会出现「点了某件的查价，查出来的是上一个词」。

### 5.4 冷却（防连点）

- 两类查询的冷却是分开计的（`query_market` 和 `search_drops` 各 5 秒），所以「掉落 → 查价 → 掉落」来回跳，正常节奏下不会互相拦。
- 会被拦的情况：5 秒内连续点两件不同道具的「查价」。第二次会被 `guard` 拦下并弹出现有的「请 N 秒后再试」提示。
- **被拦时的界面状态要对**：页签已经切过去、输入框里是新词，但结果区还是上一次的结果。这会让人以为眼前的价格是新词的。处理方式二选一，建议前者：
  - 被拦时不切页签、不改输入框，只弹提示（先过 `guard`，通过了才跳）；
  - 或者照跳，但清空旧结果。
- 后端对掉落有 1 小时缓存、对拍卖有 5 分钟缓存，命中缓存时不打站点，但前端的冷却仍然会拦。这是现有行为，本方案不改。

### 5.5 窄窗口

- 查价窗最小宽度 580px，这时右侧详情栏会收进行内（`tm-inline-detail`）。「谁掉」链接要在两种布局下都看得到。
- 掉落行在窄宽度下，道具名会被截断（现有行为）。新增的「价」按钮不能把名字挤到只剩一两个字：按钮固定宽度、不换行，名字照旧省略。
- 主窗口最小 1000px，掉落区是两列布局，每行可用宽度有限，同样按上面处理。

### 5.6 竞态

现有的 `useLatestRequest`（只认最后一次响应）已经覆盖：快速连点两件道具时，先发的请求后回来不会覆盖新结果。联动走的是同一个查询函数，不用额外处理，但验收时要测。

### 5.7 区服

查价用的是全局预设区服，联动不改变这一点。玩家在掉落页看不到当前是哪个服，跳到物价页后区服下拉框会显示，够用。

## 6. 为什么不直接在掉落表里显示价格

这是最直观的做法，但不建议：

- 一只怪的掉落表常有十几到几十条，每条一个拍卖请求。拍卖页每次约 180KB，还依赖查询凭证，站点有限流。
- 项目里所有打站点的操作都是「用户点一下才发一次」，并且有冷却。批量自动查价会打破这条约定。
- 小册子是第三方站点，不是项目自己的服务。

如果以后要做，前提是和小册子站长确认可接受的请求频率，或者对方提供批量接口。

## 7. 验收要点

在主窗口和查价窗各走一遍。浏览器里可以用 `?window=main&mock` / `?window=hud&mock` 先看界面，真实数据要在 `pnpm tauri dev` 里验。

1. 掉落页搜一只怪（如「绿蘑菇」），点某件掉落的「查价」：切到物价、输入框是这件的名字、结果是这件的拍卖价。
2. 物价页搜一件道具，点「谁掉」：切到掉落、结果里是掉这件的怪，这件在各自的掉落表里被高亮。
3. 从物价切回掉落：之前的掉落结果、展开状态、已加载的页数都还在（主窗口）。
4. 任务道具行上没有「查价」按钮。
5. 掉落行点名称区，仍然在系统浏览器打开小册子图鉴页。
6. 5 秒内连点两件的「查价」：第二次出现冷却提示，界面上不会出现「输入框是 B、结果是 A」。
7. 点一件当前没人卖的道具：显示现有的空结果提示，「最近查价」里不出现这个词。
8. 总览页「最近查价」点词跳转仍然正常（外部 seed 没被页内 seed 搞坏）。
9. 查价窗拖到最小（580×360）：新按钮和链接都看得到，行没有被撑成两行，道具名正常省略。
10. 查价窗里 `Tab` 切模式、`↑↓` 换选中项、`Esc` 两段式收起，行为和改之前一致。
11. 日间、夜间两套主题下新按钮都看得清。
12. `cd src-tauri && cargo test` 全过（含 `frontend_conventions` 约定检查；本方案不新增外链写法）。
