# 枫之助（mxd-box）

Tauri 2 + React + TypeScript 的冒险岛怀旧服桌面助手：物价查询、金价走势、怪物掉落速查、
经验统计（练级目标、角色列表、镭射小结卡片）、当前几线、开服与金价到价提醒、内存监控与到线提醒、
骗子黑名单（含剪贴板自动比对），外加两个置顶悬浮窗：
`Alt+F` 的查价窗（查价 / 掉落 / 查人）、`F10` 的经验窗（等级、经验、线号、内存）
（都可以改键，设置页里**按压捕获**）。

> 名字叫「枫之助」；包名 / 数据目录仍然是 `mxd-box` / `com.mxdbox.tool` ——
> 改标识符会把用户已有的设置与黑名单留在旧目录里，所以只改看得见的名字。

## 界面结构（0.1.6 改版起，0.1.7 / 0.1.9 微调）

> 下面很多小节是改版前写的。提到「精简悬浮窗里的金价」「基础配置页」「顶栏徽章」的地方，
> 以这一节为准。

- **主窗口**（`views/MainView.tsx`）：左侧导航 7 页 —— 总览 / 行情 / 查询 / 练级 / 提醒 / 设置 /
  关于与更新说明。
  - 侧栏底部是常驻状态区：当前频道、官方开服、内存、数据来源（小册子），再下面是主题切换和
    QQ 群。有新版本时状态区上方多一个胶囊。
  - 右上角是**预设区服**（分段按钮，每一页都在）。
  - 「总览」（`pages/OverviewPage.tsx`）：金价、练级、最近查价、提醒开关一屏看完；另有一栏
    「偏好」，关窗收进托盘和界面动效在这儿也能拨（完整说明在设置页）。
  - 「关于与更新说明」（`pages/AboutPage.tsx`）：已开源（GitHub 地址，点了用系统浏览器打开）、
    数据来源、交流群、赞赏码入口、开源组件署名、各版本更新说明。赞赏码**只有这一个入口**，
    点了才弹（`TipDialog`）：不自动弹、不挂红点、别处不提 —— 免费工具，不该让人觉得被催。
- **查价窗**（`hud`，Alt+F）：左列表 + 右详情；头部有内存和频道胶囊。
- **经验窗**（`float`，F10，以前叫「精简悬浮窗」）：等级、经验进度、每小时经验、净经验 /
  每分钟 / 距升级；头部是软件名 + 频道胶囊 + 计时。**不显示金价**。拖矮（面板 < 80px）或
  双击标题栏收成**单行条**，单行条里也有软件名和线号。
- **窗口尺寸**（`tauri.conf.json`；最小值以「所有功能都看得到」为准，前端 `useWindowSize`
  的下限要和它一致）：

  | 窗口 | 默认 | 最小 | 最小值卡在哪 |
  | --- | --- | --- | --- |
  | 主窗口 | 1264×776 | 1000×660 | 再窄侧栏收成图标条（看不到频道）；再矮侧栏状态区放不下 |
  | 查价窗 | 680×460 | 580×360 | 详情栏、页脚、频道胶囊都要在 |
  | 经验窗 | 470×282 | 470×56 | 头部和单行条都要放下「软件名 + 区服｜线 + 上次的线」 |

- 悬浮窗头部挤不下时**谁让位**写在 `styles/overlay.css`（`.ch-*` 是 `ChannelBadge` 留的钩子）：
  断线留下的「上次」优先于区服名和软件名，自己换线留下的「上次」最先让位；放不下的胶囊
  整颗不显示（折行后裁掉），不横着切半颗。
- **每个窗口只加载自己那份代码**（`App.tsx` 按 `?window=` 懒加载视图；主窗口的「行情」「练级」
  两页连同图表库 recharts 也是点进去才加载）。以前所有窗口共用一个约 790 KB 的包，经验窗和
  查价窗一行图表都不画也要先解析完；现在悬浮窗只拿公共部分 + 自己那几十 KB。
- 浏览器里调界面：`npx vite` 后开 `http://127.0.0.1:5173/?window=main|hud|float&mock`
  （`dev/tauriMock.ts`）。可选参数：`channel=live|stale|unknown|switched|none`、
  `unreadable=1|away`、`phase=idle`、`warn=1`、`goal=<目标等级>`。

## 数据来源（小册子 mxdc.dvg.cn）

这些事实都是对着真实页面核对过的，改动解析逻辑前请先看这里：

| 用途 | 位置 |
| --- | --- |
| 区服 | **只有 5 个**：`1 蓝蜗牛 2 蘑菇仔 3 绿水灵 4 漂漂猪 5 小白兔`。站点**没有「全服」**，不传 `server` 时只回蓝蜗牛 |
| 拍卖查询 | `/tools/market/?st=<凭证>&server=<1-5>&q=<关键词>`。缺 `st` 或凭证不对时服务端只渲染一句「查询凭证已过期」，结果区是空的 |
| 查询凭证 | 拍卖页里的 `<input name="st">`，会缓存复用；看到「凭证已过期」时重取一次 |
| 结果卡片 | `a.market-result-card`（不是表格！）。**结果区在 180KB 页面的最末 12KB** |
| 金价 | `/tools/price-trend/` 的报价表是前端渲染的，真实数据在 `window.PRICE_TREND_DATA` 内联 JSON（含 `history_hour` / `history_day` 快照） |
| 掉落速查 | `/api/drop-search.php?q=<关键词>&page=<n>`，**公开、不需要登录**。页面 `/tools/drops/` 是 Vue 前端渲染的，数据全在这个接口里（页面上的 `apiUrl`） |
| 怪物图鉴 | `/mob_info.php?id=<mobid>`（公开展示页） |
| 道具图鉴 | `/item_info.php?id=<id>`，**公开页、不需要登录**。基准属性与售价在 `article.gcw-client-item-tip` 里：`.gcw-client-item-props` 是属性、`.gcw-client-item-reqs` 是需求、`.gcw-client-item-upgrade` 是卷轴次数、`.gcw-client-item-footer` 是 NPC 出售价（如「出售价格：2,000 金币」） |
| 站点基建 | 阿里云 ESA 边缘（`server: ESA`），每次请求都会下发新的 `PHPSESSID` |

## 窗口、托盘与退出

- 三个常驻窗口：主窗口、**查价悬浮窗**（`hud`）、**经验窗**（`float`，以前叫
  「精简悬浮窗」，下文旧段落里两个名字指同一个窗）；另有三个用完即关的临时窗：
  开服提醒窗（`alert-toast`）、登录授权窗（`login`，微信扫码时再开一个 `login-qr` 外链窗）、
  校准蒙版窗（`calibration-overlay`）。
- 托盘图标是**常驻**的（任务栏右下角）：左键单击（双击也行）把主窗口抬回来，右键菜单是
  `显示主窗口 / 呼出 / 收起查价悬浮窗 / 呼出 / 收起经验窗（经验统计） / 隐藏主窗口（后台常驻） / 退出程序`。
  「退出程序」点下去有一道防误触（`shell.rs`）：资源管理器重启时 Windows 会补发一个陈旧的
  菜单事件，实测会让程序自己退出；现在只有**任务栏窗口还在**、或者**120 秒内右键点过托盘图标**
  时才真的退出。
- **默认点右上角的 X 是「退到托盘常驻」**（`close_to_tray` 默认 `true`）。这个工具有大半价值
  发生在主窗口不在前台的时候 —— 等开服、盯内存、游戏里按快捷键；默认「X 就是退出」的话，
  用户点一下就把这些全停了，而他并不知道自己关掉了什么。要真退进程用托盘菜单的「退出程序」，
  或者去「设置 → 通用」把这个开关关掉（总览页的「偏好」栏里也能拨）。
- 曾经不是这样：那时默认 X 就退出（因为 HUD 是常驻隐藏窗口，只要还有窗口活着 Tauri 就
  不会自动退出，所以关闭事件里显式 `app.exit(0)` 免得留下看不见的进程）。现在退回托盘是
  **有意的**默认行为，`app.exit(0)` 仍然只在「不退托盘」那条分支上跑。
- 状态开关放在 `AppState.close_to_tray`（`AtomicBool`），**不在关闭那一刻去查数据库**：
  窗口关闭事件是在主线程的窗口过程里同步回调的，那里不能抢 SQLite 的锁。

## 两个悬浮窗与全局快捷键

**它们是两个不同的窗口**（别合并，也别把两边的快捷键混成一个）：

| 窗口 | label / URL | 内容 | 默认快捷键 |
| --- | --- | --- | --- |
| 查价悬浮窗 | `hud` / `index.html?window=hud` | **一根输入框 / 三个页签：查价 / 掉落 / 查人**（+ 物品详情 + 内存徽标） | `Alt+F` |
| 经验窗 | `float` / `index.html?window=float` | **等级 + 经验进度 + 每小时经验 + 当前线 + 内存**（不再显示金价），可收成单行条 | `F10` |

另外还有一个**不属于悬浮窗**的全局键：「经验统计」的开始 / 暂停（默认 `Ctrl+Alt+P`，
在「练级」页改）。它没有窗口，只是给游戏里想开 / 停统计时用；
`HotkeyAction` 因此有三个值，`apply_hotkey` 也接受 `action = "exp_toggle"`。
给它的默认值是**组合键而不是裸键**：全局键会直接把按键从游戏手里抢走，
一个裸 `F9` 会让游戏那边再也收不到这个键，而我们检测不到游戏自己占用了它。

- 都是 `transparent` + `alwaysOnTop` + `skipTaskbar` + 无边框，各自记住位置；
  `Esc` 或窗口上的 × 收起。呼出方式是**切换**：按一次出来、再按一次收起。收起是**两步**：
  先通知页面把面板清空、画出这一帧，再真的 `hide()`（`overlay-hiding` / `overlay-shown`）——
  直接 `hide()` 会把最后画出来的那一帧留在系统那边，下次呼出先贴出来的是它，
  用户看到的就是「闪一下才出现」（0.1.9 修）。
  - 查价窗里的 `Esc` 是**两段式**：输入框里有内容时只清空，再按一下才收起窗口。
    以前无条件收起 —— 打了一半字、或者输入法正在组字时按 `Esc`（预期是「取消这次输入」）
    整个窗口就没了。组字期间（`isComposing`）的 `Esc` 一律不管，交给输入法。
- 两个悬浮窗都**能拖边改大小，内容跟着窗口重排**（容器查询，`styles/overlay.css`；缩放热区和
  尺寸记忆在 `components/WindowFrame.tsx`）。以前经验窗是「量内容高度再 `setSize`」，改版后
  反过来：窗口多大、内容排多大，放不下的行自己收起来，最矮时变成单行条。最小尺寸见上面
  「界面结构」。
- 快捷键在 `hotkeys.rs`：
  - **注册结果可见**。以前 `register` 的返回值被丢掉，键被别的程序占用时界面什么都不说，
   用户看到的就是「设了快捷键按下去没反应」。现在每个键的注册状态（含失败原因）
   都存在 `hotkeys` 里，设置页直接显示。
  - **状态变化会广播**（`hotkeys-changed`）。界面上的「按 X 切换显示」这类提示以前只在
    窗口挂载时读一次 —— 主窗口和悬浮窗都是启动时就建好的常驻窗口，所以在设置页改完键，
    别处会一直停在旧键上。现在 `apply_all` 每次成功注册后都会 `emit`，HUD 标题栏跟着变。
  - **凡是界面提到快捷键的地方，一律走 `useHotkey(action, fallback)`**（`src/lib/hotkeys.ts`）：
    先问一次当前值，再订阅广播。这个 hook 是被同一个 bug 攒出来的 —— 侧栏底部那个
    「呼出 / 收起查价窗 (Alt+F)」按钮和黑名单页的一句提示都**写死**了 `Alt+F`，用户把键
    改成 `Alt+D` 之后它们还在教一个按了没反应的键。
    - 那种按钮的处置是**删掉**，不是改成动态：悬浮窗本来就有全局键、设置页里有
      「测试呼出 / 收起」，多一个入口只是多一个会过时的显示；
    - 「看得见但会骗人」的信息比没有更糟 —— 这条和「不要用假数据兜底」是同一类要求。
- **三个页签共用一根输入框**（`mode`），而不是三个窗口：要用它的时候你正开着游戏，
  能看见的窗口只有这一个，多一个窗就多一个快捷键、多一个「刚才那是哪个窗」的问题。
  模式只影响「回车交给谁」和结果区（`runSearch` 里的三行分派）。
  - **改完当场生效**。以前要重启进程才生效，用户改完试一下没反应就以为没保存成功。
    现在 `apply_hotkey` 会立刻「全量重注册」（先全部注销再逐个注册）——
    三个键里有两个撞在一起时**两边都不注册**、并当场把冲突报出来（交给系统去撞的话，
    谁先注册谁生效，用户看到的是「按这个键弹出的是另一个窗口」）。
  - 设置页的输入框是**按压捕获**（`HotkeyInput`，点一下直接按组合键）：以前是文本框，
    要用户自己打 `Alt+F`，可键盘上并没有一个叫 `+` 的主键，「`Alt` 还是 `AltLeft`」
    也没人知道，于是经常存进一个解析不了 / 收不到事件的串。捕获用 `event.code`
    （物理按键，不受输入法影响），修饰键单独按下不算一个组合。
  - 按键 → 窗口的分派在 `dispatch_hotkey`：回调只拿到「按的是哪个键」，三个动作各注册
    一个键，不能「按一下就两个都切」。
  - **捕获期间必须先注销全局快捷键**（`hotkeys::pause` / `resume`，设置页在捕获开始 / 结束时调）。
    这一条不是锦上添花，是按压捕获能不能用的前提：全局键走 OS 的 `RegisterHotKey`，键一旦
    注册，系统会把那次按键**直接投递给我们的消息队列**，webview 收不到 `keydown` ——
    于是想「把 `F10` 改成别的键」时按 `F10`：前端毫无反应（`preventDefault` 拦不住 OS 级
    分发），悬浮窗反被呼了出来。
    - 恢复时用「最近一次收到的配置」（`desired_slot`）而不是回数据库读：捕获结束与
      `apply_hotkey` 是两个并行 invoke，到达顺序不确定，回库读有可能拿到改键前的旧值，
      用户会看到「改完又变回去了」。
    - 恢复路径只有一条，挂在 effect 的 cleanup 上：捕获成功、`Esc` 取消、点到别处、
      直接离开设置页，全都走它，所以不会出现「改键改到一半把快捷键弄没了」。
- 设置页里有一行小小的 `.setSize` 之外没有别的魔法：悬浮窗内容里不放任何需要输入的东西。
  （待确认：这句原文语义不明，未能在代码里找到对应；经验窗里确实没有输入框，
  但查价窗有一根搜索框。）

## 全局预设区服

- `default_server_id` 存在设置表里（**只有这一处状态**）：主窗口的拍卖查询、查价悬浮窗、
  经验窗都从它取值。
- 以前两边各自 `useState(1)` 写死蓝蜗牛，谁都没记住用户在哪个服，于是每开一次窗口都要
  重新选一次，而且在悬浮窗里选完、主窗口还是老样子。现在谁改了都写回数据库，
  并通过 `default-server-changed` 事件广播，所有窗口一起切（`lib/presetServer.ts`）。
- `set_default_server` 会校验 id 真的在 `mxdc_client::SERVER_IDS` 里：不校验的话
  存进一个不存在的 id，之后每次查询都只静默返回空结果，看起来却像「站上没有这个道具」。
- 切换入口有三处，写的是同一个值：**主窗口右上角的分段按钮**（每一页都在）、
  查询页物价搜索旁边的区服下拉框、查价窗里的下拉框。设置页、行情页对比表、
  总览金价列表里原来的切换入口在 0.1.7 去掉了（入口重复）；
  经验窗不再显示金价，也就没有切服入口。

## 当前频道（几线）

- 游戏只在「切换频道」窗口里显示当前线，磁盘、注册表和日志里**都不写**
  （2026-09-28 把安装目录、LocalLow、注册表、启动器日志、SDK 日志和几个第三方
  工具都翻过一遍，零命中）。但它是**一条线一个服务端端口**：**每台机器固定负责
  3 条线，端口固定 8585/8586/8587**（组内第 1/2/3 条），换线就断连重连。
- 每个区服用哪一段机器是**部署出来的**，只能实测录入（`FARMS`）：
  * **绿水灵**：`.76`–`.95` 连续 20 台（1–3 线在 `.76`，58–60 线在 `.95`）；
  * **蓝蜗牛**：`.27`–`.48` 里**去掉 `.31`、`.39`** 两台（这两台不在这个服的
    列表里），1–3 线在 `.27`，58–60 线在 `.48`（现场扫了 11 个点核对）；
  * **蘑菇仔**：`.49`–`.75` 里**去掉 `.51`–`.54`、`.58`、`.60`、`.61`** 七台，
    1–3 线在 `.49`，58–60 线在 `.75`（现场扫了 13 个点核对）；
  * **漂漂猪**：`.140`–`.165` 里**去掉 `.143`、`.146`、`.148`、`.154`、`.155`、`.159`**
    六台，1–3 线在 `.140`，58–60 线在 `.165`（现场扫了 21 个点核对）；
  * **小白兔**：`.166`–`.187` 里**去掉 `.171`、`.185`** 两台，1–3 线在 `.166`，
    58–60 线在 `.187`（现场扫点 + 穷举反解核对）。
  五个区服的机器号互不重叠（整片机器按区服切开分，段内的洞是别的东西在用）。
  扫点时**必须一条一条按顺序切**：漏切会让对号整体错位（小白兔踩过一次，
  靠穷举反解才发现漏切了 19、22）。
- 录入方法：换线扫一遍（每个组取一条线核对），然后加进 `FARMS` —— 别再想着
  「用公式推」：曾经按「末段 = 75 + 组号」的公式推，绿水灵对、蓝蜗牛就错。
- **没录入的区服一律显示「线号未知」**，绝不按形状硬猜；用户点一下真实线号
  就按节点记住（`channel_host_bases`，JSON：地址 → 基准），之后那台自动。
  手动校准过的基准优先于农场表（手动永远最大）。
- 实现（`channel.rs`）：每 3 秒查一次**系统 TCP 表**里游戏进程的 ESTABLISHED
  连接（`GetExtendedTcpTable`）—— 不读游戏内存、不截屏、不注入。
- 状态（`channel-update` 事件 + `get_channel_state`）：`auto` / `manual` /
  `uncalibrated`（形状认不出又没校准）/ `stale`（上次记录，游戏没开）。状态里还带
  `server`（区服名，节点在 `FARMS` 里才有）和 `recent`（最近待过的线）。
- **登录 / 选角色界面也是 `uncalibrated`**：那时连的是登录服，本来就没有线号。所以界面在
  这个状态下只说「进角色后会自动显示」，校准格收在一行链接后面 —— 直接摊开的话，用户在
  登录界面点一下就会给登录服记一个错的基准。
- **上次在哪条线**（0.1.7）：掉线重登往往进的不是原来那条线。每次「离开一条线」记一笔
  （`ChannelVisit`，最多 5 条，存在设置 `channel_recent`）：直接换线走的 `dropped = false`，
  连接断了之后才到别的线的 `dropped = true`；回到列表里的某条线时把它拿掉 —— 列表永远是
  「除了现在这条以外，最近待过的」。分不清掉线和主动下线（看到的都是「连接没了」）；
  换线卡了 6 秒以上也会被记成断开。
- 显示（`components/ChannelBadge.tsx`）：两段式胶囊「区服｜N线」+ 虚线胶囊「上次 N线」
  （断线留下的是琥珀色，自己换线留下的是灰色；游戏没开时只剩「上次」这一颗）。出现在
  主窗口侧栏状态区、查价窗头部、经验窗头部和单行条。点开是最近待过的线 + 校准格（兜底用）。
- 真机探针：`cargo test --lib -- --ignored probe_channel_port --nocapture`。

## 开服提醒（轮询、声音、通知）
- 提醒 = 蜂鸣 + 任务栏闪烁 + **我们自己的右下角提醒窗**（`alert.rs`）。
  五类内容共用这个出口、各自冷却：**开服提醒**（10 分钟）、
  **剪贴板命中黑名单**（90 秒，标题带角色名）、**金价到价提醒**（按到价自身的
  「退回去才重新上膛」规则，见下节）、**内存到线提醒**（只在游戏开着时，连续 30 秒
  在警戒线上方才响；回落到线下 5 个百分点、且距上次满 10 分钟才重新上膛，见 `memory.rs`）
  和**测试**（绕过冷却）；
  提醒窗按 `source` 换图标与配色（黑名单命中整窗红边）。
  - 声音**不能只靠 `MessageBeep`**：Windows 默认声音方案里它能触发的
    `SystemAsterisk` / `SystemExclamation` 都被映射成很轻的
    `Windows Background.wav`（本机注册表实测），戴着耳机打游戏基本听不见。
    所以是两层：先 `MessageBeep(MB_ICONEXCLAMATION)`，再 `PlaySoundW` 放一段
    系统通知音；放不出来就退回 `kernel32!Beep` 单音。三个都是直接 FFI 调的
    （`user32` / `winmm` / `kernel32`），**不再起 powershell 子进程** —— 以前那种
    写法会先闪一个黑色控制台窗口再消失，而且 `print!("\x07")` 在 GUI 程序里
    根本没有控制台，等于什么都没做。
  - **`tauri-plugin-notification` 的原生 Toast 不能当作提醒的依靠**：这是未安装版
    （`bundle.active = false`，没有开始菜单快捷方式、没有注册 AppUserModelID），
    Windows 会把 Toast **静默丢弃**——`show()` 返回成功、日志里一个错都没有、
    屏幕上一片安静。实测就是这样：点「测试开服提醒」听得到蜂鸣，通知压根不出现。
    所以真正的可见通道是自绘的提醒窗（`AlertToastView`，`?window=alert`）：
    无边框、`always_on_top`、画在主屏右下角（实测 `2560x1440` 上落在
    `2128,1219,2536,1416`，即右/下各留 24px）。原生 Toast 仍然顺手试一次，
    以后要是出了正式安装版它会自动开始生效。
  - 提醒窗**刻意不抢主窗口焦点**（只闪任务栏 + 弹自己的小窗）：开服那一刻用户
    多半正在游戏里，`set_focus` 会把游戏踢到后台，比少一次提醒更糟。
  - 提醒窗用完即 `close()`：这是个内存监控工具，常驻一个 WebView2 要多占几十 MB，
    正是它要帮游戏省下的内存。20 秒后自动关闭，点「知道了」立刻关。
  - 提醒页有「测试开服提醒」按钮，走的是和真开服**同一条出口**（`alert::dispatch`）：
    能听到、能看到提醒窗，真开服时就一定会响。
    （测试走 `fire_open_alert_force`，**不动冷却时间戳** —— 否则「点一次测试，
    五分钟真开服了」会被那次测试按下去，就成了最糟的「测试能响、真开服不响」。）

## 小册子「开服监控」（开服提醒的唯一数据源）

`mxdc_monitor.rs` 订阅站点自己的开服判断：<https://mxdc.dvg.cn/tools/server-monitor/>
每分钟探一次游戏登录入口，把结论写在一个只回 JSON 的接口里，页面上的「状态变化」
就是它。

> 早期版本还有一条「自己填一个登录网关地址做 TCP 握手探测」的路（`server_probe.rs` +
> `gateway_detect.rs`），现已整体移除：那个地址会随机房轮换而**默默失效**，
> 而「静静地变错」正是告警工具最糟的失败模式；站点这边的判断既不用填地址、
> 也更接近「官方开服了没有」。

- 接口：`https://mxdc.dvg.cn/tools/server-monitor/api.php`，无需登录。
  形状（2026-09 实测，单测里就是这份真实响应做的 fixture）：

  ```json
  { "ok": true, "now": 1790046981, "interval": 20, "stale": false,
    "snapshot": {
      "checked_at": 1790046961,
      "status": "login_recovered",
      "login":    { "name": "登录入口", "status": "greeting", "detail": "握手正常" },
      "official": { "status": "unknown", "detail": "缓存标记维护（时效待确认）" },
      "changed_at": 1789984081,
      "history": [ { "at": 1789984081, "status": "login_recovered",
                     "login": "greeting", "official": "unknown" } ] } }
  ```

  ⚠️ `snapshot.login` 是**对象**，而 `history[].login` 是**字符串** —— 同一份数据
  两种形状，改这块时别混用。所有字段都容错（缺了不影响其它部分）。
- 状态码 → 说法**照抄站点页面**（对照小册子时不会觉得两个工具在说两件事）：
  `login_recovered` = 服务器正常 / `maintenance` = 服务器维护中 /
  `confirming` = 正在确认状态 / `unavailable` = 状态暂不可用；站点以后加了新状态码会
  原样带出来（`未知状态（xxx）`），**不要**偷偷归到「未知」。
- 报警规则（`feed_should_alert`，全是单测锁着的纯函数）：
  - **只有真的「从非正常 → 正常」才报**：`confirming` 不算开服 —— 维护一延长就误报，
    而误报一次就会让人开始不信这个提醒。
  - 首次采样只建立基线；**除非**这次「正常」是刚刚发生的（`changed_at` 在 10 分钟内）——
    维护刚结束就打开工具箱，正是最该被提醒的那一刻。
  - 站点自报 `stale: true`，或 `checked_at` 超过 5 分钟没更新（采集器卡住）→ 不报警。
- `alert.rs` 里的 10 分钟冷却保证同一场开服不会响两遍。
- 抓取失败**不清空**已有结论：只把原因写进 `error` 并在卡片上标明「这只是我们没问到
  站点数据，不代表服务器状态异常」。站点抖一下不该让用户紧张。
- 提醒页的卡片里有：当前状态 / 三个证据（游戏连接、官方消息、开服提醒）/「立即刷新」/
  「测试开服提醒」/「打开小册子监控页对照」/ 最近 6 条状态变化，外加开关和拉取间隔档位
  （20 / 30 / 60 / 120 秒，默认 30 —— 站点自己 20 秒采一次，问得更勤没意义）。
- 日志里只在**首次采样**和**状态变化**时记录，便于事后回溯「那天几点开的服」：

  ```
  小册子开服监控：（首次采样） → 服务器正常（检测于 2026-09-22 11:29:01，站点采集间隔 20 秒）
  开服提醒窗已显示（右下角置顶，20 秒后自动关闭，visible=true）
  ```
- 怎么确认「它真的在轮询」：提醒页的监控卡片上有「检测于 HH:MM:SS（xx 秒前）」；
  主窗口侧栏的状态区也有一枚随状态变色的圆点和一个词（开服中 = 绿 / 维护中 = 黄 /
  取不到数据 = 红）。

## 金价到价提醒（`meso_alert.rs`）

- 盯的是**全局预设区服**的「1 元能换多少万金」（总览页最大的那个数，越大金币越便宜）：
  `above` = 涨到这个数或以上提醒，`below` = 跌到这个数或以下提醒，可以只填一个。
  设置在「提醒」页（`MesoAlertCard`），改完立刻生效并马上查一次。
- **开着才查**：每 10 分钟一次，走和「行情」页同一个带缓存的取数函数
  （`commands::load_meso_report`），所以不会比原来多打站点；没开或两个数都没填时什么请求都不发。
- **只在跨过去的那一下响**（`decide`）：同一个区服、同一个方向响过之后不再响，价格退回去
  超过 1% 才重新上膛 —— 不然价格在阈值上下晃一次就响一次。状态存在设置 `meso_alert_state`
  （形如 `3:above`），所以重启不会把已经响过的再响一遍；改设置、换预设区服会清掉它。
- 出口是 `alert::fire_meso_alert`：和开服提醒同一套响铃 / 闪任务栏 / 弹窗，但**不共用**
  那个十分钟冷却（两件事共用一个冷却只会互相吃掉）。
- 取不到报价就等下一轮：没有数据不等于「没到价」，更不能拿旧数据凑。

## 避坑黑名单（查一个人 + 自动嗅探）

目标是「在**要交易的那一刻**能查到这个人」，而不是「有一个能录名字的表格」。

- **四档结论**（`blacklist.rs::judge`，纯函数 + 单测）：

  | status | 含义 | 会不会弹提醒 |
  | --- | --- | --- |
  | `hit` | 同名 + 同服（或记录标了「全服通用」） | 会 |
  | `other_server` | 名字一样，但记录挂在别的服 | 不弹，只提示「自行判断」 |
  | `similar` | 名字互相包含（≥3 字的记录 vs ≥2 字的查询） | 不弹 |
  | `clear` | 本地库没有 | 不弹 |

  为什么不是二值的「安全 / 危险」：游戏里同名很常见，直接判死就是误伤好人；
  反过来把 `clear` 说成「安全」又等于给骗子背书。
- **名字先归一化再比**（`normalize`：去各种空白、全角转半角、英文小写）：
  从网页或聊天里复制来的名字常带空格 / 全角字符，原来按 `player_name = ?` 精确比，
  「张三 」和「张三」会被当成两个人。
- **同名同服只留一条**（`Database::add_blacklist` 里带归一化比对的 upsert）：
  重复录入是**更新**原因与类别，导出给朋友时不会是一串重复。
- **剪贴板嗅探在 Rust 侧**（`spawn_clipboard_watcher`）：
  - 只用 `GetClipboardSequenceNumber` 判断「剪贴板有没有换过内容」，变了才真去读文本
    （`CF_UNICODETEXT`，先 `GlobalSize` 再读，不越界）；
  - 文本要**看起来像角色名**才比（2–16 字、无换行 / 空格、不是纯数字、不是 JSON / URL）；
  - **只有 `hit` 才响铃 + 弹提醒窗**（90 秒冷却，同一个名字不重复报）——
    「别的服同名」「名字很像」拿去响铃，很快就会让人学会无视这个提醒；
  - 和界面是否打开无关：主窗口收进托盘、切到别的页签都照常生效。
    原来那版是前端 `setInterval` 读剪贴板，只挂在黑名单页上 —— 而你要查人的时候
    恰恰是在游戏里交易，最不可能停在这一页。
  - 开关是设置里的 `blacklist_watch`（默认开），黑名单页上有开关；
    比对全在本地，内容不出本机、不写日志。
- **三个入口**：主窗口黑名单页的「查这个人」、查价悬浮窗的「查人」那一栏、
  以及剪贴板自动嗅探。后两者是给「正在游戏里」准备的。
- **导入 / 导出 JSON 的界面入口本轮已移除**（用户要求先不做，后期再评估）。
  Rust 侧的 `export_blacklist` / `import_blacklist` 命令与它们的单测都留着，
  以后恢复不用重写逻辑 —— 但真要恢复时得先把「别人发来的名单能不能信」想清楚：
  黑名单是照名字比对的，一份别人塞进来的名单可以直接毁掉一个人的风评，
  而且这个工具对它的处置是「弹提醒」，不是「仅供参考」。

## 怪物掉落速查（`mxdc_client::search_drops`）

一个输入框同时支持四种查法（站点自己支持的）：**怪物名**（这只怪掉什么）、
**道具名**（这件东西哪只怪掉）、**怪物ID**、**道具ID**。

抓下来的一组实测事实（改解析前先看这里）：

* **字段类型不能想当然**：`results[].mob.hp` / `exp` / `pad` / `mad` 是**字符串**，
  而且老怪物（尤其是任务怪）整块数据是空的（`hp: ""`、`level: 0`、`icon: ""`）；
  `boss` / `matched` 是**数字** `0/1`，不是布尔。所以 `flexible_flag` 把
  `0/1`、`true/false`、`"1"/""` 全读成布尔 —— 按死一种类型的话，站点哪天换个写法
  就是整个响应解析失败（对查询功能来说比少一个字段糟得多）。
* **概率直接用站点算好的串**（`chanceText`，例如 `0.007%`），不自己拿 `chance`
  换算 —— 两个工具显示不同的概率是最没必要的困惑。
* 图标取回来是 `/dbsource/...`，统一补成绝对地址；各条记录在小册子上的页面地址
  也在后端拼好（`pageUrl`），前端不需要知道 `/item_info.php?id=` 这种约定。
* **键名对前端是一份契约**：站点给 `itemid`，发给前端的是 `itemId`（
  `#[serde(rename(deserialize = "itemid", serialize = "itemId"))]`）。
  单测 `drop_search_serializes_with_the_keys_the_ui_reads` 把每个键都钉住了 ——
  否则改个 rename 的症状是「界面上某一块空白」，最难查。
* 掉落资料是**静态数据**，缓存 1 小时；但**空结果不进缓存**（站点偶发地会回
  “没结果”，一旦写进去用户接下来一小时都查到空 —— 和拍卖查询踩的是同一个坑）。

手工验证：`cd src-tauri && cargo test --lib probe_live_drops -- --ignored --nocapture`
（拿三种关键词打真实接口，只打摘要日志）。

### 分页与默认展开（`hud` 里的「掉落」页签，与主窗口同一套数据）

* 站点一页只给 **12 只怪**（`pageSize=12`）：搜「锅盖」共 4 只、1 页到头；
  搜「蘑菇」共 34 只 / 3 页；搜「药水」共 360 只 / 30 页。所以悬浮窗底部要有
  「加载更多」，而且**追加**而不是冲掉前面的（否则搜「蘑菇」只看得到 12 只，
  看起来像「只有这么多只怪」）。翻页用的是**当初搜的那个词**（`drops.meta.keyword`），
  不是用户可能已经改过的输入框内容。
* **默认摊开哪几只看这次查询的意图**，不是一刀切：搜**怪物名**（无魂猴）→ 名字里含
  关键词的那几只摊开，直接看到它的数据和掉落；搜**道具名**（锅盖）→ 一只都不展开，
  缩略行里已经写着命中那条的概率，收起状态正好一眼比较「哪几只怪掉、掉率多少」。
  不能拿「有没有 matched 掉落」当判据：实测搜「无魂猴」时站点也把孽咒娃娃标成了
  matched，那样搜怪物就永远不会自动展开。翻页时**保留**已展开的选择。
* 悬浮窗里显示的是「共 N 只怪物 · 命中掉落 M 条」，不是 `results.length` ——
  `meta.total` 才是怪物总数，`results.length` 只是当前已加载的。

## 经验统计（`exp/` 模块）

自动从游戏画面里读 `EXP 427096(46.09%)` 那一行，算每分钟 / 每小时收益和升级还需多久。

**不挑分辨率，也不用先校准**：游戏界面会随分辨率 / 界面缩放整体放大缩小
（1080p 字高 7px、1440p 约 9~10、768p 约 5、4K 约 14），读取链按
「手动框（比例坐标）→ HUD 锚点（主路径）→ 旧版本学下来的自动框 → 整幅画面
多尺度候选 + PP-OCR 兜底」找那一行（`reader.rs` 模块头）。
找得到就自动记住位置（连续两帧稳定才落库）；找不准也可以手动框一次，
框的是**比例**，换分辨率不用重框。

**F10 经验窗上是等级、进度和三个数**（每小时经验 / 每分钟经验 / 距升级）。会话、角色列表、
历史、阶段效率、小结卡片等在主窗口的「练级」页。

没点「开始统计」时也在读（每 3 秒一次，`IDLE_INTERVAL`）：只显示当前等级和进度，不记收益，
这时三个数都是「—」（「测量中」只在统计开始后才成立）。游戏没开或最小化时界面只说
「游戏没开」或「游戏窗口最小化了」一句（`lib/expRead.ts` 的 `gameAway` / `gameAwayText`），
不摆「校准位置」—— 没有画面可框，校准解决不了。

**人不在游戏里时少干重活**（`tracker.rs` 的 tick）：登录 / 选角色界面上没有经验行，也没有
小地图，每 3 秒把整幅画面搜一遍、再对着登录画面跑地图 OCR 纯属空转。「在游戏里」满足
任意一条就算：正在统计 / 上一轮读成了 / 游戏连着一条认得出的线（`channel` 模块）。都不满足时
并不是不读 —— HUD 锚点那条主路径照常每轮都试，只是**整幅搜索降到 15 秒一次**
（`reader.rs` 的 `OFFLINE_SEARCH_INTERVAL`）、地图先不认。判断不了（没录入的区服、启动头几秒）
时宁可按「在」处理，或者至少保留降频后的兜底，不会把读数关死。

**练级目标**（`set_exp_goal`，存在设置 `exp_goal_level`）：填一个目标等级，状态里的 `goal` 给出
「到目标等级 0% 还差多少经验、按本段平均时速还要多久」。全靠累计经验做减法（`goal_progress`），
中间要升几级都不用管。没在统计时也给「还差多少」，时间要有时速才有。入口在「练级」页的
「本段」卡片里（`ExpGoalRow`），经验窗页脚也会显示。

### 等级怎么定：经验表优先，**等级框兜底**

`700(0.07%)` 这种「刚升级」的帧，经验表是**多解**的：几十个等级的累计经验都装得下
这 700 点，谁都说不准（`table::validate` 判 `Ambiguous`）。这时候用**等级框**
（HUD 锚点推出 or 手动校准的等级区域）读到的 `Lv.56` 顶上 —— 所以「开始统计」
不会被这种帧拦住，也不需要重启软件（`tracker::start_level`）。

（用户报的 bug：掉线回登录界面再进游戏后一直「还定不出等级」，即使等级框都框选
成功了也不行；根因就是这里以前只看了经验表。）

地图名同理补了一道：OCR 结果和本地记过的名字**等长、差一个字、且唯一候选**时
拉回来（「随法密林」→「魔法密林」），差两个字或有两个候选就不猜（`snap_map_name`）。

### 这一版修掉的三件事（都有真机实测依据）

#### 1. 抓屏方式 —— 「经常识别不到」的头号原因

旧实现从**屏幕 DC** 抓「屏幕上那个矩形」。游戏上面压着任何窗口（浏览器、聊天窗、
别的工具）时，抓回来的就是**那个窗口**的像素，于是识别层报「画面上没有经验那一行」，
用户读成「不在角色里 / 去校准一次」—— 方向全错。

同一个探针在「游戏可见」和「游戏被整块白色盖住」两种情况下各跑一遍，比较抓到的
墨点占比（经验条那一行的合理值在 20% 上下）：

| 场景 | 屏幕 DC（旧实现） | PrintWindow(0) | PrintWindow(2) |
| --- | --- | --- | --- |
| 游戏可见 | 20.2% ✅ | 20.2% ✅ | 20.2% ✅ |
| **游戏被整块盖住** | **100.0% ❌**（抓到那层白底） | **20.2% ✅** | **20.2% ✅** |

`PrintWindow` 抓的是**窗口自己**，合成在哪一层、上面压着谁都不影响 ——
这就是参考工具（冒险岛国服怀旧服经验统计小助手）说明里那句「后台截屏」的意思，
也是它「不会说找不到画面」的原因。现在整条链路都走它，屏幕 DC 只作兜底。

> ⚠️ `PrintWindow` 永远从**窗口**左上角开始渲染整个窗口（含标题栏），
> 所以要按**窗口**尺寸申请位图、再裁出客户区那一块。按客户区尺寸申请会拿到标题栏
> （这个错误我在写探针时也犯过一遍，所以在这里写下来）。

真机验证（`reader_reads_without_foreground`，**不把游戏切到前台**）：

```text
场景一：游戏可见          成功率 10/10   抓法 Window
场景二：游戏被全屏白色盖住  成功率 10/10   抓法 Window   ← 读数逐字相同
```

#### 2. 字形表必须完整（不做运行时学习）

经验那一行的字符集是**封闭**的 17 个符号，那就没有任何理由在运行时去「学」。
旧实现只内置了一部分、缺的靠自动学习补，结果是**时好时坏**：真机上 50 帧里只有
**8 帧**读得出来。原因很具体 —— 20 级的经验值大量含数字 `1`，而 `1` 正是缺的那个：

```text
20216 是 20 级的升级所需
12302 ÷ 20216 = 60.85%   ← 真机帧，含 1
12145 ÷ 20216 = 60.08%   ← 真机帧，含 1，两个 1
```

`1` 的点阵就是从上面那一帧里直接取出来的（`.#|##|.#|.#|.#|.#|.#`，只有 2 像素宽）。
`builtin_font_is_complete` 钉住「17 个符号一个不少」。

顺带删掉的：百分比反算（估算值）、经验条交叉验证、`exp_table_trusted`。
理由分别是：

* 字形全内置之后，经验数字永远读得全，估算那条路不再需要（它是为「缺字形」打的补丁）；
* 经验条交叉验证原本是为了防「认到别的窗口里的数字」—— 现在抓的是游戏窗口自己，
  这种情况**不可能发生**了，这道检查失去了存在理由，还带来误杀风险；
* 经验表已经用真机两个等级的帧精确验证过（`427096/926689`、`12145/20216`），
  不再需要一个「信不信这张表」的开关。

早期还删过一次「手动校准」（那时它是运行时学字形）。现在它回来了，但换成了另一套模型：
**只记位置、不学字形**（见下一节）。位置是比例坐标，与分辨率 / 字体都无关。

#### 3. 字段定位不能看字形间隙

数字 `1` 的字形只有 **2 像素**宽，而它占的字格是 5 像素 —— 右边会空出 **3 像素**。
旧实现用「空隙 ≤ 2 算贴在一起」把经验字段从整条状态栏里切出来，这个 3 像素的空隙
就把字段从中间切断，整帧作废。更糟的是有些帧会被悄悄**截掉开头那位**：
`12302(60.85%)` 读成 `2302(60.85%)` —— 一个看起来挺像真的的错数字。

现在按**纯结构**解析：从最右边的 `)` 往左严格按 `数字(整数.两位小数%)` 吃字形，
空隙多大都无所谓。**任何一位对不上就整帧作废**，绝不给出半个数字。

唯一必须看空隙的地方是**数字的左边界**：左边那个字形认不出时，它可能是被漏掉的数字。
判据是实测出来的 —— 数字**内部**空白最多 3 列，`EXP` 标签到数字之间空 9 列，
取中间值 5（`MIN_NUMBER_GAP`）：够远才放行，否则整帧作废。

### 换分辨率 / 界面缩放下怎么找那一行（学网页版枫记）

**核心做法是从网页版枫记（fj.need.run）移植过来的**（`exp/hud.rs`）：
不靠「按分辨率比例猜位置」，而是用 HUD 自己的结构**确定性定位**：

1. 找血条的**亮色边框**——逐行扫出亮的横向长条（长度 70~350px）；
2. 三个条（HP/MP/EXP）的水平间距是固定的 `[0,168,344]`（参考坐标系），
   从任意两条的距离反推**缩放** `sx`；
3. 按 `sx` 把 **HP/MP/EXP 标签的像素模板**（`assets/mxdc-hud-templates.json`，
   直接从网页版抠出来的同一套像素）缩放后逐点比对（平均通道差 + 相关度），
   对得上才算锚点；
4. 找不到就在 1/2、1/4 降采样图上再找（金字塔）。

锚点一定住，三个区域就都是「锚点 + 固定偏移 × 缩放」：

| 区域 | 参考偏移 | 用途 |
| --- | --- | --- |
| 经验行 `EXP xx(xx.xx%)` | `+343×sx, -14×sy`，高 `16×sy` | 主读数（字号无关，读出后过经验表自检） |
| 等级框 `Lv.xx` | `-457×sx, -10×sy`，高 `28×sy` | 经验表定不出等级时兜底 |
| 地图名 | 小地图图标模板（39×14）→ `+48×sx, +43×sy`，宽度按面板背景色裁 | 自动认地图名（真机实测读出「猴子沼泽地8」） |

真机验证（1080p、人在角色里）：锚点误差 **0.0**（模板逐点命中）、缩放 1.000，
经验行 OCR 读出 `707420 / 76.34%` 并通过经验表。

**读取顺序**：手动框（快速路径，只抓一小块）→ HUD 锚点自动定位（任何分辨率 / 显示
缩放 / 窗口尺寸都成立）→ 旧版本学下来的自动框 → 整幅候选带 + OCR 兜底。
HUD 锚点之后的读数在 `hudread.rs`：窗口化就原样读；无边框全屏被**非整数倍拉伸**时，
按锚点量出的缩放把文字区**还原回原生像素**再认字（真机 1366×768 拉到 2560×1440 那种）；
系统 DPI 又糊一遍的走逐字灰度比对；都不行才把数字那一块喂给 PP-OCR。
**手动校准只作为兜底**：读不到时（比如 HUD 被面板挡住、界面皮肤不认识）再让用户框一次，
框出来的仍是比例坐标。

**自动学习的规则**（`reader.rs`）：第一条成功读数换算成比例框先**暂用**；
下一帧在同一位置也读得出来（交并比 ≥ 0.7）才落库。自动档连续 2 帧读不到就丢掉重学；
**手动框永不被自动覆盖**。手动框连续 3 帧读不到只标记「校准可能失效」并把提示带进
`ExpStatus.region_lost`，由界面提醒用户重新框，不静默换位置。HUD 锚点结果按客户区
尺寸缓存（同一尺寸不重复扫全图），找不到时有 15 秒冷却、连续读不到 3 次会重找。
还有一条 0.2.0 修「换角色后经验读不出来、要关掉重开」的规则：HUD 锚点处**看得到
EXP 标签、数字却读不成**连续若干帧（`HUD_UNREAD_LIMIT`，从 5 帧起、每丢一次锚点
阈值翻倍、80 帧封顶）时，丢掉锚点重新定位 —— 卡住的不是读数，是那个已经对不上的锚点。

**手动校准**现在的主路径是**游戏画面蒙版**（`views/CalibrationOverlayView.tsx`）：
点「手动校准」后 `open_calibration_overlay` 在游戏客户区上盖一层**透明置顶窗**
（按客户区**物理像素**定位），里面把框外压暗、直接在真实游戏画面上拖框。
**顶栏可以选校准类型：经验条 / 地图名 / 等级**（各自一条比例记录，互不影响），
**拖完自动测试、认对了自动保存（不关蒙版，可以接着校准其它类型）**；
没认出来就留在蒙版上提示「请重新拖动框体」。
为了让你看见游戏，开蒙版时会把游戏抬到前台、把主窗口先让开
（用户显式点的动作，平时绝不抢焦点）；关掉时主窗口自动回来。
**按钮全在顶栏**：经验条就在画面最底下，底部工具条会正好压住它。
命令开不出蒙版（游戏没开 / 独占全屏等）时自动退回老浮层
（`CalibrationDialog.tsx`：整幅截图 → 2× 放大拖框 → 放大微调 → 测试，只做经验条）。
两条路都走同一组命令：`test_exp_region` 拿临时框立刻读一次，**不落库**、也不动已有校准
（旧实现是「先保存、再等下一轮采样」，点一次测试就已经改了用户的选择，测失败连退路都没有）；
`save_region_profile` 才写库，下一轮采样自然接手。

**三种类型的验收口径**（`ExpReader::test_region`）：经验条要过经验表双数自洽；
地图名要过 `looks_like_map_name`（汉字为主、1~12 字）；等级要能从 OCR 文本里抠出 1~120。

**校准过的区域在运行期怎么用**：
* 经验条 —— 主读数框，读不到自动退回整幅搜索（见上）；
* 地图名 —— `exp::map` 的指纹和 OCR 都改用这个框（`refresh` 的 `override_rect`），
  不再猜 Scaled / Absolute 模式，换分辨率也不用重框；
* 等级 —— 只在**经验表定不出等级**的帧（升级瞬间的 `0(0.00%)`）才去读它，
  当兜底喂给账本；正常帧一次 OCR 都不多花。

**入口**（都不藏在设置里）：主窗口「练级」页「开始统计」旁的**手动校准**按钮；
读不到时的失败横幅里的**校准位置**；F10 经验窗读不到时那句「未识别到经验条」
旁边的**校准位置**（悬浮窗直接开蒙版；开不出来才退回主窗口的截图浮层）。

### 每分钟 / 每小时是怎么算的（分母是「观察了多久」）

**一句话：窗口内净涨了多少 ÷ 窗口本身有多长。**

这里踩过一个用户先发现的坑。早先的实现把分母写成「有增量的那些帧的时长之和」——
看着等价，其实**打怪是一阵一阵的**：一分钟里可能只有 26 秒在涨经验，另外 34 秒在
跑图、捡东西、站着不动。于是那 26 秒的收益被当成一整分钟的量报了出去，
真机上表现为悬浮窗写「每小时 103,298」而同一时刻的小结卡片写「4.2 万 / 时」，
差了 2.5 倍（卡片用的是整段平均，那个是对的）。

现在的口径和卡片完全一致：窗口长度取「会话有效时间」与窗口的较小值 ——
刚开统计时窗口还没长满，就按实测的那一段折算。分子不是把单帧增量加起来，
而是存一条**单调的累计管线**（`GainPoint { active_secs, total }`）在窗口边界上**插值**，
于是「最近 60 秒」是真正的 60 秒滑窗，不会因为采样点的落点而抖。

`a_minute_with_gaps_is_not_extrapolated_from_the_gaps` 这条测试钉住的就是那个 2.5 倍。

### 小地图上的地图名：**上 PP-OCR，真认字**

会话里那一栏「在哪练的」以前要用户自己填，现在**自动认**。

#### 为什么不能自己拼一个中文识别

小地图里那一行是 **11 像素高、抗锯齿、带描边和渐变的中文**。这个字号下：

* Windows 自带的 `Windows.Media.Ocr` 读不出来（下表）；
* 「拿字体渲染候选再比对」也没有字体可用。

| 喂给 Windows OCR 的东西 | 读出来 |
| --- | --- |
| 64 像素清晰黑字（对照） | `坠 落 主 义 金 银 岛` ✅ |
| 24 像素清晰黑字 | `坠 落 主 义 金 银 岛` ✅ |
| 16 像素清晰黑字 | `坐 落 主 义 金 岛` ⚠️ 错两个字 |
| 12 像素清晰黑字 | `金 裉 島` ❌ |
| **游戏里的 11 像素地图名** | 空（二值化 / 填洞 / 灰度 / 原图，六种喂法全空） |

#### 网页版枫记（`fj.need.run`）怎么做，我们就怎么做

**两个「枫记」不是一回事**：网页版**确实自己认地图名**，桌面版（我们本地那个
`冒险岛国服怀旧服经验统计小助手`）**不做**（只带 `tessdata/eng.traineddata`，
`MapName` 是个用户输入属性）。网页版的做法拆出来是：

1. 内置**像素模板**（`minimap` 39×14 等）在画面里多尺度扫描，定位小地图 → 推出地图名区域；
2. 用 **PaddleOCR PP-OCRv6 + onnxruntime-web(WASM)** 做真正的中文识别。

我们照后半步做，前半步不需要（位置是固定的）：

```text
小地图里截一行 → 等比缩放到高 48 → 归一化到 [-1,1] → PP-OCR rec 模型 → CTC 解码
```

* **模型**：`assets/ppocr_rec.onnx`（`PP-OCRv6_tiny_rec`，4.3MB）＋
  `assets/ppocr_dict.txt`（6906 项 = blank + 6904 个字 + 一个空格）。
  来自 PaddleOCR 官方（**Apache-2.0，免费**），**打包进 exe** ——
  不联网、首次运行也不用下载（网页版是运行时下载并缓存的）。
* **推理**：`tract`（**纯 Rust**）而不是 onnxruntime —— 后者要随包带一个二十多兆的
  `onnxruntime.dll`，而这是「拷一个 exe 就能用」的工具，多一个 DLL 就多一种坏法。
  代价是慢一点，但我们只在换地图时跑一次（48×204 的一小块）。

真机实测：地名 `金银岛` 置信度 **0.996**，地图名 `废弃都市` 置信度 **0.933**。
`tract_matches_onnxruntime` 这条测试钉住「tract 和 onnxruntime 结果完全一致」。

#### 两个踩过的坑

* **字典少一个 blank，全是乱码。** 模型输出 6906 类，而解码表是
  `blank + 字典 + 空格`；少一个 blank 所有下标整体偏一位，读出来是
  「釜铸岢」这种乱码 —— 而「乱码」看起来很像「模型不行」，会把人往错的方向带。
* **ONNX 里的动态维度符号必须显式绑。** 这个模型的输入是
  `[DynamicDimension.0, 3, 48, DynamicDimension.1]`，而图里别的节点在导出时
  已经按**具体值**做过形状推断，于是 tract 报
  `Impossible to unify Sym(DynamicDimension.0) with Val(1)`。
  得用 `set_symbols` 把两个符号绑成具体值（批次 1、宽度按这一行实际算出来的宽度）。

#### 认不出来时怎么办

**区域现在是自动定位的**：HUD 锚点（`exp/hud.rs`）→ 小地图图标模板（39×14）
→ 地图名那一行（`+48×sx, +43×sy`，宽度按面板背景色裁）。手动校准地图名只是兜底、
以及自动定位认不出时的覆盖手段。真机实测：自动定位后 OCR 认出「猴子沼泽地8」。

`looks_like_map_name` 再卡一道（字数 1~12、置信度 ≥ 0.60、一半以上是汉字）：
太低就当没认出来。**宁可没有地图名，也不要一个认错的** ——
一张写着别的地图的卡片发出去，比没写地图更没有用。

数字和尖括号是后来补的两课（0.1.9 / 0.2.0）：自动定位给出的框是**整条面板**那么宽，
模型输入限宽 320，长地名被横向压扁到 58%，半个字宽的数字和 `<` 就没了
（「猴子沼泽地3」读成「猴子沼泽地」，「地铁二号线<第3地区>」读成「地铁二号线-的地区」）。
现在先把框**裁到有字的那一段**（`crop_to_text`）、再走**不压扁**的识别路径，并把
白字 + 深色阴影**换成白底黑字**（`to_ink`）——11 像素的 `3` 贴着阴影时，原样喂模型
会在 `3` / `8` / 丢掉之间摇摆（真机 147 种裁法只有 46 种读对），现在稳了；
尖括号只留成对的（`tidy_map_name`），半边括号比没有更像认错。

认出来之后按小地图那一块的**像素指纹**（FNV-1a）存进 `exp_maps` 表当缓存：
下次来这张图直接命中，不用再跑一遍模型。指纹要**连续两次一致**才采纳
（切场景/小地图重绘会让某一帧不一样，闪来闪去比晚 2 秒认出来糟得多）。
旧版本读丢了数字的名字已经写进了库：库里的名字**不带数字**时会现场再读一遍，
只有「多了数字」才替换（`settle_name` / `restores_digits`）—— 用户自己起的叫法、
OCR 认错的字，一律以库里为准。

地图名会显示在悬浮窗的经验卡片上，并在保存这一段时**自动写进历史**。

> 这条路线的取舍写在 `exp/map.rs` 的模块文档里，包括上面那张实测表 ——
> 免得以后有人觉得「不就是认几个字吗」再试一遍。

### 升级那一帧永远不是负数

同类工具被吐槽的「升级后数据全部变成负数」，根因是本级经验每升一级归零，
直接拿 `新经验 - 旧经验` 去算就是一个巨大的负数。这里把 `(等级, 本级经验)` 换算成
**跨级单调的累计经验**（`table::cumulative`），所有加减法都在累计值上做：

```text
增量 = 累计(新等级, 新经验) - 累计(旧等级, 旧经验)      // 永远 ≥ 0
```

升级、连升两级、跨整级自动对。「这一帧到底发生了什么」被收成**一个函数、四种出口**
（`table::Advance`），每种出口的值都是非负的：

| 出口 | 什么时候 | 处置 |
| --- | --- | --- |
| `Gained { level, exp, gained, level_ups }` | 正常推进（含升级） | 记增量（由累计值相减得到，**保证 ≥ 0**）。`exp` 是这一帧生效的本级经验，要拿它当下一帧的基准 |
| `Loss { level, exp, lost }` | 同一级里经验变少 | 死亡掉经验：如实报出来，**不记负收益**，也不算成换角色，基准挪到新值继续 |
| `Shifted { too_big }` | 这一帧自己自洽、只是和上一帧接不上 | 不计增量、**基准挪到当下**（不挪的话下一帧还是接不上，统计就永久停摆）；`too_big` 另记一笔 |
| `Unclear` | 这一帧自己就自相矛盾 | 什么都不记，**基准不动** —— 下一帧接着按上一帧的好值算 |

**升级和死亡会互相冒充**，所以让它们同台竞争：同一份「上一帧 46.09% → 这一帧 0.44%」
既能讲成「升到下一级、凭空多出 50 万」，也能讲成「死亡、只少了 42 万」。按 if/else 让
某一种优先，一次死亡就会被记成一笔凭空的 50 万经验 —— 用户看到的时速直接翻倍，
而这一段的其它数字全是好的，根本查不出来。所以三种解释（升级 / 同级增长 / 死亡）
放进同一张表里比，按**离预期增量最近**挑一个；拿不到预期值（刚开统计、还没攒出速率）
时退化成「挑变化最小的那个」。

**挑选器不改变任何解释的合法性**：它只在都合法的解释里选一个，永远不会让一个合法解释
变成「不记」。枫记拿类似的量当**门槛**（小于 `8 × 中位数` 的增量直接丢弃），代价是
「打得慢的那一段被悄悄抹掉、报出来的数字偏高」，这里不这么干。

### 认错比认不出更危险

* **每次读数都自证**：`经验 ÷ EXP_TABLE[等级-1] ≈ 括号里的百分比`。
  读对了必然自洽，读错了几乎必然无解 —— 不通过就判「这一帧不算数」，绝不喂进统计。
* **抓不到就暂停，绝不记 0**：最小化 / 不在角色里 / 画面空白 → 暂停采样并写明原因。
  报不出数就是说不出数，不用上一次的值凑合。
* **认不出的字形整帧作废**（见上文左边界判据）：宁可读不到，也不给半个数字。
* **一帧的增量不可能超过一级所需的全部经验**：这种帧能过经验表校验，和上一帧一比
  却是天文数字 —— 丢掉并记账。`advance_never_produces_a_negative_number` 拿全表
  1~120 级 × 各种经验 / 百分比组合扫过，真实升级另有
  `a_real_level_up_is_read_as_a_level_up` 这类单测钉着，不会被误伤。
* **重立基准时等级必须装得下这个经验值**（`table::level_holding`）：找不到就继续往上扫。
  这一条钉的是一个会把整段统计打死的坑 —— 如果留下「等级 1 却装着 3 万点经验」这种
  自相矛盾的基准，下一帧的累计经验比谁都大，于是**之后每一帧都接不上**，一句数都不再记。
  一次任务奖励就能触发它。
* **平时不读等级**：等级由（经验, 百分比）算出来 + 账本自己推，少读一个字段就少一个
  失败点；只有经验表定不出等级（刚升级那几秒）时才读一次等级框（见「等级怎么定」）。

### 这一段数据能不能信

一个「每小时 30 万」的数字，如果有一半时间是读不到画面的，那它既不是真的也不假 ——
它只是**不能拿去比较**。所以每段会话都算一份 `SessionQuality`（结论 + 一句理由），
存进库、显示在历史列表上：

| 结论 | 什么时候 |
| --- | --- |
| 数据完整 | 画面覆盖 ≥ 95%，且一帧都没被校验拦下 |
| 可参考 | 画面覆盖 ≥ 80%，拒绝帧 ≤ 5% |
| 不建议用于比较 | 其余情况 |

两条特意分开的轴：**画面覆盖**（我们能不能看见 = 数据可不可信）和
**有效打怪占比**（你是不是一直在打 = 玩法）。挂机多不代表数据有问题，
混在一起说会让「挂机 70%」看起来像程序坏了。

**时间口径**：可用读数的每一帧都会推进会话时钟（哪怕这一帧的增量不可用）——
时钟不推进的话，被拒的那段时间会被从分母里悄悄抹掉，报出来的速率就偏高。
暂停是「精确扣除」：恢复时把下一帧标成**只立基准**，暂停期间你一直在打也无所谓，
那一段不算进这一段；而等级**接着用**（不像清空重来那样要重新定级，
升级那一瞬的 `0.00%` 还会多解，于是恢复之后常常空转好几帧）。

### 会话与历史

* 程序启动**不会**自动开始统计；点「开始」才算一段；「暂停」连采样一起停
  （滚动窗口跳过暂停时段，否则去吃饭回来「一小时」会被白拉低）；
* 「开始」的门槛只有一条：能定出等级（经验数字和百分比互相自洽；升级瞬间
  经验表多解时用等级框顶上，见下）；
* 「结束」先问一句要不要计入历史，计入才写库（连这一段的质量结论一起存）；
* 历史存**每分钟**一个采样点 + 一张会话表，会话里带起止两端的**累计经验**，能跨级求和；
* 不满一小时就按实测区间折算，并在旁边写「实测 12 分钟」——不能把 12 分钟的数
  当一小时的平均报给用户；
* **恢复后效率**（借鉴枫记）：一段「读不到画面」之后，主速率被弄脏了，
  从恢复后的第一个可信帧单独算一个时速；
* **阶段效率**（借鉴枫记）：按升级把会话切成一段一段，每级各自的时速分开看；
* **预计升级时间**：距升级的经验 ÷ 当前滚动时速，停手时自动消失（不猜）。
* 历史按**角色**分开（0.2.0，见下）：点角色列表里的一个角色只看它的；单条可以删、
  也可以单独分享（用同一套卡片重画一张），「清空」是整库清。

### 角色列表（0.2.0，`exp/character.rs` + `db.resolve_character`）

练两个号的时候，不分角色的话历史里两个号的记录会混在一起。所以每个角色的**身份**单列：

* **身份是状态栏名字那一块的像素指纹**，不是认出来的字 —— 角色名是玩家自己起的，
  中文 / 字母 / 数字都有，OCR 偶尔认错一个字很正常；拿认出来的字当身份，认错一次
  就多出一个「新角色」，历史跟着劈成两半。指纹换了分辨率会变，所以一个角色可以挂
  多个指纹（`exp_character_marks`）；新指纹读出来的名字和已有角色一样时并到那个角色上。
* 名字和职业（`LV.` 右边那两行）是 OCR 读出来**给人看**的：职业那一行单独记指纹，
  转职后重读；名字读不出来也不影响身份（显示「未命名角色」），过几秒再试。
* **改名 / 移除在界面上**（`ExpCharacters.tsx`）：名字认错了字可以自己改（`renamed`
  标记之后 OCR 不再盖回去）；从列表里拿掉一个角色**不删它的练级记录**，记录只是
  不再标是谁练的 —— 下次登录这个角色会重新记进列表。
* **历史按角色分开**：点一个角色，历史、汇总和曲线只看它的；看全部时每行标出是哪个
  角色练的。这一段归哪个角色：会话开始时认出来就挂上去；还没认出来就先挂着，
  认出来之后补上。
* **统计中换角色会自动暂停**（`note_character`）：两个号的经验记进同一段，时速和升级数
  都是错的；界面上的提示会说明，切回原来的角色再点继续。另外，名字那一块正在变
  （刚换角色还没确认是谁）、经验刚恢复还没重新看到名字、或者登录的已经是另一个角色时，
  这一帧的读数**只更新显示、不进这一段的账**（`unsettled` / `suspect` / `is_foreign`），
  免得把新角色的等级和经验写到旧角色头上。

### 地图与小结卡片（`lib/shareCard.ts` + `save_share_card`）

* **地图是自动认的**（见上面的「小地图上的地图名」），输入框里显示的就是认出来的那个；
  **用户改过一次就一直用他改的**（`manualMap` 优先于 `status.map_name`），改完跟着
  这一行进历史、进卡片。历史里出现过的地名会变成输入框旁边的快捷按钮；
  认不出时空着，不编一个地名上去。
* **小结卡片是画出来的，不是截图**：界面截图里一半是按钮和滚动条（还常常叠着
  别的窗口），发给群里既没重点也泄露多余信息。卡片只画这一段的结论 —— 地图、
  时间段、等级区间与进度条、净经验、时速、分段效率、数据可信度，页脚是软件名。
  样子是**竖版集换卡**：N / R / SR / SSR 四档**只跟自己的历史比**（数据不完整、
  不满 5 分钟、历史不到 3 段的不硬评，这一段升了级提一档），配一个称号
  （「新纪录」「连升三级」「肝帝」…）。canvas 按 2 倍分辨率画、导出再乘 1.5，
  发出去放大也不糊；列宽按数字宽度自动缩字号。
* **角色形象**（0.1.9）：卡面上可以放一小块角色画面 —— 从当前游戏画面里**自己框**
  （角色不一定在正中，旁边还有别的玩家和宠物，自动找错一次发出去的就是别人），
  也可以导入现成的图（纸娃娃导出的透明 PNG 也行）；选一次存在本机（localStorage），
  之后每张卡都用它；不带形象时就画一个纹章。框的位置按比例记住。
* **发出去两条路**：弹窗里「复制图片」把 PNG 转成 `CF_DIB` 放进系统剪贴板
  （`copy_share_card` → `clip_image.rs`；桌面版微信 / QQ 认这个格式），到聊天框
  Ctrl+V；「保存为图片」走 `save_share_card`，负责解 base64、**验 PNG 头**
  （IPC 传大字符串真的会截断，不验就会在用户图片文件夹里留一张打不开的 `.png`）、
  存到 `图片\枫之助\<地图名>-经验小结-<时间戳>.png`，
  最后用 `explorer /select,` 把它**摆到用户面前**。
* 文件名要过滤：地图名可能是用户改过的，`/ \ : * ? " < > |` 一律去掉、截到 20 字
  （`share_card_file_names_are_sanitized`）。
* 结束确认框里带着**冻结的整段快照**（`ExpPending.summary`）和一个「分享」按钮：
  会话一结束 `session` 就空了，没有这份快照，确认框里就只剩两个数，卡片也就画不出来了。

### 两处界面上的事（都是用户先发现的）

> 这一小节写的是 0.1.6 改版之前的 F10 悬浮窗（金价 / 内存 / 经验三张卡片）。现在的经验窗
> 不显示金价，排版见「界面结构」；留着是因为下面几条取舍（只留一个记录时长、「未涨经验」和
> 「测量中」分开说）仍然有效。

**F10 悬浮窗按「卡片」排，不按「三行字」排。** 只有三块，自上而下：**金价 → 内存 → 经验**。

* 金价：一个最大的数字，**区服对照直接跟在同一个区块里**（点一下切服，数字跟着变），
  不再是「上面一个价、下面一行按钮」两处；
* 经验：**卡片**。左边最大的数是「经验 / 小时」（用「万」收短），右边两格是等级和净经验，
  底线一行是每分钟和升级信息。顶栏是「本次记录时长 + 开始/暂停 + 结束」，
  **结束键点完就地给出「计入历史 / 丢弃」**，不用切回主窗口；
* 标题栏写的是**软件名「枫之助」**，不写「精简悬浮窗」这种功能名。

数字旁边**只留一个「本次记录时长」**，不再在每个数字后面挂「实测 26 秒」：
那既挤，又把「时长」和「可信度」两件事混在一起说（可信度由旁边的「画面 xx%」表达）。

速度是 0 时显示**「未涨经验」**而不是「测量中」—— 前者是没在打，后者是数据还不够，
混成一句会让人以为再等等就有了。

**悬浮窗用鼠标拖边框放大缩小**（无边框窗、`resizable: false`，右侧 / 下边 / 右下三条热区，
宽度 240~680px）。**拖拽是自己用指针事件算的，不走系统的 resize 循环**：

> 一开始用 `startResizeDragging`（系统那条路）：系统按鼠标位置设窗口尺寸，我们又按
> 「等比缩放」调 `setSize` —— 两边抢同一个窗口，表现就是一直抖。现在拖拽只更新宽度
> state，`setSize` 由高度 effect 统一做（带防抖），窗口只有一个写的人。

缩放用外层容器上的 CSS `zoom` + 固定 `BASE_WIDTH`，**宽度由 state 决定**：

```text
zoom = 宽度 ÷ 340
```

拖右边按宽度算 zoom、拖下边按高度算（÷ 内容高 + 16 —— 那 16px 的 padding 也跟着
zoom 缩放）、拖右下角看哪一维变化更大；高度仍然跟着内容走，宽度记在 localStorage。

> 一开始把 `zoom` 加在**根节点**上，结果放大之后右边被裁掉 —— 根节点的 zoom 不改 `vw`，
> `w-screen` 还是那么宽。改成「外层容器固定 340px 宽、只加 zoom」，渲染出来正好是
> `340 × zoom`，也就是窗口宽度。高度用 `offsetHeight`（布局像素，不受祖先 zoom 影响）
> 乘倍数，不用 `getBoundingClientRect()` —— 后者「zoom 算不算进 rect」在不同 Chromium
> 版本里答案不一样，会时对时错。
>
> 以前是标题栏 −／＋ 按钮点着缩放；用户反馈「点开始的时候按钮被撑大」——
> 根因是那一行（状态胶囊 + 地图名 + 两个按钮）在 340px 里放不下，
> 按钮文字被折成两行。现在按钮带 `shrink-0 whitespace-nowrap`、标题行可换行，
> 并且缩放改成拖边框（想多大拖多大），按钮行不再被挤压。

**日间主题下提示文字看不清。** 根因是主题的「明度阶梯镜像」把两个角色搞反了：
深色主题里 `slate-600` 比 `slate-500` **更暗**表示「更弱」，浅色主题里就镜像成了
`#a8b4c4` —— 压在白面板上对比度只有 **2.0:1**，等于没有。同一个问题还有一组
「浅底上的深字」：`emerald-200` / `sky-200` 在深色主题里是亮色文字（压在半透明深底上），
浅色主题里底变成了淡绿/淡蓝，字却还是亮的（对比度 1.1:1）。

现在浅色主题下：

| | 改前 | 改后 |

**界面文案只留必要的**：不写「这是干什么的」「为什么这样」，只留标签和状态

### 防连点（`lib/throttle.ts`）

按钮背后大多是**真的去打小册子那个网站**（拍卖查询、金价、掉落速查、版本自检…）。
这些请求不快，用户点一下没立刻看到东西就会再点一下 —— 同一秒发出去五六个请求，
对用户是白等，对那个站点是不必要的压力（而且它不是我们自己的服务）。

所以凡是「按一下就会出去发请求」的地方都先过一道 `guard(key, 标签, 秒数)`：

* 第一次点 → 放行；
* 冷却期内再点 → **拦下来**，并且广播一条提示（`ThrottleToast` 挂在 App 上，
  主窗口 / 查价悬浮窗 / 经验窗都看得到）：「拍卖查询：请 5 秒后再试」。

**只提示不静默拦截是刻意的** —— 静默拦下来，用户只会觉得「点了没反应、这软件坏了」。
冷却分三档：查询类 5 秒、重活（版本自检、登录校验）10 秒、改本地状态 3 秒。

用节流（throttle）而不是防抖（debounce）：防抖是「等用户停下来再发」（适合输入框），
按钮要的是「立刻发一次，然后短期别再发」，两件事不一样。

覆盖到的：`query_market`、`search_drops`、`get_meso_report`、`refresh_server_monitor`、
`check_for_update`、`get_item_detail`、`test_open_alert`。

逻辑本身用 `node .tmp/throttle_check.mjs`（把 `throttle.ts` 直接编译出来跑）
验过 11 项：第一次放行、冷却期拦下、提示里带操作名和剩余毫秒、不同操作互不影响、
窗口过期后放行、退订后不再收到。（脚本没有随仓库提交，这段是当时的自检记录。）

所以以前到处是各写各的 `div className="p-5 rounded-xl bg-slate-900/60 border ..."`，

### 悬浮窗：三张卡片 + 按钮必须「立刻有反应」

> 「三张卡片」是 0.1.6 改版前的排版；按钮那两条仍然有效（现在在 `lib/useExpSession.ts`，
> 经验窗和总览页共用）。

自上而下**金价 → 内存 → 经验**三张卡片：

* **金价**：头部写「10 分钟刷新」和最近一次取数时间；正文是最大的那个数字；
  下面**两列对齐**的区服对照（价格右对齐、按价从高到低、当前服高亮），点一下切服；
* **内存**：一行，超阈值整张卡变红；
* **经验**：头部是「经验 + 本次记录时长 + 开始/暂停/结束」，正文是
  「经验 / 小时（最大）+ 等级 + 净经验」，页脚是「每分钟 + 距升级」。

**两个真机上报上来的毛病，根因都在「拿什么当界面状态」上：**

1. **点暂停之后马上点开始没反应。** 是我上一轮加的防连点误伤：开始/暂停/结束是
   **本地状态切换、不发任何请求**，却套了 3 秒冷却，于是「暂停完想马上开始」
   被自己的冷却拦掉。现在它们**不吃冷却**，只用 `busy` 防重入。
   冷却只留给真正发请求的地方（拍卖、掉落、金价、版本自检…）。
2. **点按钮要等一两秒才有反馈。** 采样间隔是 1~3 秒，而界面只监听 `exp-update`
   事件 —— 事件没来界面就不动。现在改成：点下去**先按预期改本地状态**（乐观更新），
   同时用**命令的返回值**（后端直接把新状态回给我们）覆盖，事件退化成兜底。

## 更新说明（`lib/changelog.ts` + 「关于与更新说明」页 + 启动弹窗）

两处看的是**同一份数据**：「关于与更新说明」页（`pages/AboutPage.tsx` 里的 `UpdateNotes`），
和换版本时启动弹的那一次窗（`VersionDialog`：除了列条目，还有一个「下载到桌面」按钮，
见「版本与更新」）。

**发版时要做的只有一件事：往 `RELEASES` 的**最前面**加一条。** 写法守两条：

1. 只写**用户能感觉到的变化**（「升级不再出现负数」「不怕被别的窗口挡住」），
   内部重构不写 —— 那是给读代码的人看的，在 README 里；
2. 一条一句话，动词开头。写不下一句话，就说明这件事还不值得进更新说明。

**「只弹一次」放在后端判**（`take_version_greeting`）：

```rust
let seen = db.get_setting("last_seen_version");
if seen.as_deref() == Some(current) { return None; }   // 同一个版本只弹一次
db.set_setting("last_seen_version", current);
Some(current)
```

放后端有两个理由：

* 前端每次开窗、WebView 重载都会跑一遍挂载逻辑，把「见没见过」记在前端就会重复弹；
* 版本号只有一个权威来源（编译时定死的 `CARGO_PKG_VERSION`），前端不用自己维护。

第一次安装也会弹（没有记录 = 没见过）—— 新用户第一次打开就该知道这东西能干什么。
后端说版本变了、但 `RELEASES` 里没有这一版（发版时忘了写）时**不弹空窗**，只记一条日志。

## 打包给朋友（便携版）

Tauri 会把前端产物**编进 exe**，所以发布物就是单个可执行文件，不需要装任何东西：

```bash
pnpm tauri build
# 产物：src-tauri/target/release/mxd_box.exe（拷出去时改名成 枫之助.exe）
```

打包给别人的几个要点：

1. **exe 里没有任何个人数据。** 设置、Cookie、黑名单全在跑起来的那台机器的
   `%APPDATA%\com.mxdbox.tool\mxd_box.db` 里（数据库在首次启动时自己建），
   exe 本身是编译产物。发布前可以直接查一遍：
   `grep -c -a -F "<cookie 里的某个值>" 枫之助.exe` —— 应当全是 0。
2. **不要把本机的 `mxd_box.db` / `logs/` 打进压缩包**（它们在 AppData 下，正常也
   不会被带上）。别人第一次打开会自动建一份干净的库：未登录、默认区服蓝蜗牛。
3. **要写使用说明**：未签名 exe 会被 SmartScreen 拦（「更多信息 → 仍要运行」），
   以及需要系统的 Edge WebView2 运行时（Win10 1803+ 一般都有）。
   压缩包里放一份 `使用说明.txt`，能省掉朋友一半的疑问。

实际发布的压缩包内容就两样：`枫之助.exe` + `使用说明.txt`（解压即用）。

4. **发布只用 `pnpm tauri build`，不要用裸 `cargo build --release`。** 实测过一次：
   裸 cargo 构建出来的 exe 里带着 `C:\Users\<用户名>\Desktop\mxd-box\src-tauri`
   （资源脚本里的图标绝对路径）**而且版本信息还是改名前的旧产品名** —— 说明那次构建
   复用了上一轮的 codegen 产物。`pnpm tauri build` 会重新生成，出来的 exe 干净。
   发布前跑一次自检脚本，两件事一起查（个人数据 0 命中 + 编进去的前端是新版）：

   ```bash
   python scripts/check-share-exe.py     # 结果必须是「✅ 可以发出去」
   ```

5. **`src-tauri/.cargo/config.toml` 里的 `--remap-path-prefix` 别删。** Rust 会把
   `file!()` 与 panic 位置原样编进二进制，未处理的 exe 里有上千条
   `C:\Users\<你的用户名>\.cargo\registry\src\...\tauri-2.x\src\...` ——
   谁拿到 exe 都能读到你的 Windows 用户名和目录结构（不影响功能，但没理由发出去）。
   发了版后可以直接验：

   ```bash
   python -c "d=open('枫之助.exe','rb').read(); print(d.count(b'C:\\\\Users'), d.count(b'Administrator'))"
   # 应当都是 0；路径变成了 /build-home\.cargo\registry\...
   ```

   换一台机器构建时，把那两条前缀改成那台机器的路径即可（改错只是不生效）。

## 设置怎么分页（`FloatSettings` / `AlertSettings` / `SettingsManager`）

按**什么时候会去改它**分，而不是按实现模块分：

| 页 | 放什么 |
| --- | --- |
| 设置 → 通用（`SettingsManager`） | 关闭到托盘、界面动效、小册子登录凭证、版本与更新 |
| 设置 → 悬浮窗与内存（`FloatSettings`） | 两个悬浮窗的呼出键（按压捕获）、内存警戒阈值、「到线时提醒」开关（总览页「提醒」卡片也有一个，写的是同一个值） |
| 提醒（`AlertSettings`） | 开服监控开关与状态、拉取间隔、测试提醒；金价到价提醒（`MesoAlertCard`） |

（0.1.6 改版后「基础配置」「悬浮窗与内存」并成了「设置」页的两个页签，开服提醒是侧栏的
「提醒」页。预设区服在 0.1.7 挪到主窗口右上角，不在设置里了。0.1.9 在通用里加了「界面动效」
开关，总览页另有一栏「偏好」放着同样的两个开关。下面的演进过程是改版前写的。）

演进过程值得记一笔：最早 6 张卡片一屏铺完（用户的原话是「像是把一堆东西揉在一个地方」），
然后改成「一个设置页 + 三张分组卡片 + 保存全部配置」，用户的实际反馈是「感觉像是把一堆东西
揉在一个地方」依旧成立 —— 因为还是要在同一个页面里先选一组再看。现在是**三个独立的导航页**。

### 为什么没有「保存」按钮了

拆开之后每一页都是**改完立刻生效**：

- 内存警戒线松手就写库（`set_memory_threshold`）、快捷键按下去就重注册（`apply_hotkey`）、
  预设区服点了就广播（`set_default_server`）；
- 新加的 `patch_settings` 只改**传进来的那几个字段**（`monitor_enabled` /
  `monitor_interval_sec` / `close_to_tray` / `blacklist_watch`），供开服提醒页、
  基础配置页和总览的提醒开关用。

原来是「提交整份设置」（`save_settings`），它拆开之后有一个很隐蔽的 bug：A 页加载了一份设置，
用户又去 B 页改了东西，再回 A 页点保存就把 B 页的改动盖回旧值了。按字段改没有这种可能。
另外「未保存的改动」这个状态跨页存不住（组件会卸载），而它一旦在切页时被丢掉，用户就
**静默地**失去了刚才的修改 —— 比没有这个标记更糟。

登录凭证是唯一的例外：手动粘贴的那份有个自己的「保存凭证」按钮（扫码那条路仍然自动落库
并验证）。

## 版本与更新（`update.rs`）

**只提示、不安装。** 这是便携版、没有签名，自动更新要么得改成安装包
（要保管一对签名密钥，私钥丢了老用户就再也升不了级），要么得自己写「下载 → 退出时改名
旧 exe → 写入新的」这种替换流程，而它的失败模式是「朋友的程序坏了」。所以这里只回答
一个问题：**有没有新版本**？有就给个按钮，用系统浏览器打开下载页。
（换版本启动弹窗里另有一个「下载到桌面」：`download_update` 只把新版 ZIP 拉到桌面，
不替换正在跑的 exe —— 替换那一步永远交给人，下载失败就不会把便携版变成打不开的半成品。）

地址是**编译进二进制的常量** `update::DEFAULT_UPDATE_URL`（一个固有的夸克分享页）：
界面上没有地方能改。以前有一个 `update_url` 设置项，已经删掉了 —— 让用户自己去填一个
网盘地址，等于把「有没有新版本」这件事交给他配置（而且地址一换，已经发出去的那版就
静默失效，用户那边不会报错，只是再也不提示）。现在的约定是：**新版传到同一个分享页**
（替换旧文件、链接不变），常量就永远不用改。留空 = 不检查。

三种解析，按顺序试：

1. **JSON 清单**（最可靠）：`{"version":"0.1.1","url":"...","notes":"..."}`，
   键名宽容（`version`/`latest`/`ver`/`tag`、`url`/`download`/`link`）；
2. **夸克网盘分享**（`quark_share_id` + `quark_file_names`）：它的分享页是个前端渲染的空壳，
   11 KB 的 HTML 里**一个文件名都没有**（实测过，`version_from_page` 在那里永远读不到东西），
   所以要走它的两个接口：`sharepage/token` 换 `stoken`、`sharepage/detail` 取列表。
   两个都不需要登录；分享设了提取码 / 被取消时会明确报出夸克自己的原话
   （「分享不存在」这种）。列表要**逐层看**（`pdir_fid` 从根目录往下走，上限 3 层 /
   8 次请求，没进去看的文件夹会在报错里点出来）—— 因为分享有两种常见形态：
   zip 直接放在分享根目录，或者建一个文件夹把 zip 装进去。**只读第一层时，
   第二种会读到文件夹名（`枫之助`）而永远算不出版本号**，这个错误真发生过一次
   （用户建了个同名文件夹，程序就一直报「没能确认」）；真读不到时错误信息会把
   读到的名字报出来，方便判断是「文件没传」还是「程序没读对」；
3. **分享页的文件名**：找「枫之助」后面 60 个字符内的 `x.y.z`，取最大的那个。
   所以压缩包要命名成 `枫之助-0.1.1.zip`（`scripts/release.py` 就是这么打的）；
   改名成别的东西（`枫之助最新版.zip`）等于把更新通道掉，程序只能报「没能确认」。

夸克那条是**未公开接口**，夸克随时可能改。所以它排在最后，而且失败时把原话说出来而不是
笼统地说「检查失败」：真失效了，用户至少能分出是分享链接的问题还是程序的问题；
最坏的结果也只是「没能确认有没有新版本」。

两条容易踩的坑，都有单测钉着：

- **页面模式必须要求三段式**（`0.1.1.` 这种带尾点的也算）。允许两段的话，分享页上的
  文件大小 `5.7 MB` 会被读成版本 `5.7.0`，然后就永远提示「有新版本」；
- **没读到 ≠ 已是最新**。连不上、页面上没有版本号，都要说成「没能确认」并把原因写出来。
  把「没问成」说成「已是最新」等于告诉用户不用更新，而事实是我们根本不知道。

界面上与更新有关的地方，都不需要用户填任何东西：

- **侧栏小胶囊**：只在真的检测到新版本时出现（启动时自己查一次），点一下用系统浏览器
  打开下载页；
- **设置 → 通用 → 版本与更新**：显示当前版本（来自 `get_build_info`，不写死）、一个
  「检查更新」按钮（走同一个 `check_for_update`）和一个「打开更新页（网盘）」链接。
  链接的地址是**问后端要的**（`get_update_page_url` 返回 `DEFAULT_UPDATE_URL`），
  界面里不写第二份 —— 否则换个网盘就会出现「程序去 A 页检查、界面把用户引到 B 页」。
  三种结果分开说：有新版本 / 已是最新 / **没能确认（带原因）**；
- **换版本的启动弹窗**：有一个「下载到桌面」（`download_update` →
  `update::download_to_desktop`）：从分享页换临时直链下载 ZIP 到桌面，只收 HTTPS、
  超过 512 MB 停、内容不是 ZIP 就报错、同名不覆盖；**不碰正在跑的 exe**。

发版流程（`scripts/release.py` 把前四步串起来了）：

```bash
python scripts/release.py 0.1.1      # 改三处版本号 → pnpm tauri build → cargo test → 自检 → 打包
# 然后把桌面上的 枫之助-0.1.1.zip 传到那个固定的分享页（地址就是 update.rs 里的
# DEFAULT_UPDATE_URL，打完包脚本也会把它打印出来），替换旧文件、链接不变；
# zip 直接放分享根目录、或者放进一个文件夹里都可以（程序会往下看几层目录）。
# 上传后可以验一次真接口：
cd src-tauri && cargo test --lib -- --ignored real_quark_share
```

改版本号本身也是发版的一部分，而且**必须改**：分享页上留着旧版本的包时，朋友的程序
算出来的结论会是「已是最新」，他永远不会知道自己手上的是旧版。（单侧的真网络自检
`real_quark_share_is_readable` 默认跳过，发布前后手动跑一次就好。）

两个踩过的坑，脚本里都处理了：

- **打包前要退出正在运行的枫之助**（它会锁住 `枫之助.exe`，`copy2` 抛的 `PermissionError`
  只有 Windows 错误码，看不出该干什么）。现在会直接说「先退出程序」并给出重跑的命令；
- **`--skip-build` 只跳过编译，不跳过拷贝，且只能用于当前版本的重打包**。它无法证明旧 exe 与新版本号相符，
  所以三处版本号有任一变化就必须重新构建；脚本会在改版本号前拒绝这种组合。

## 开发约定（都是踩过的坑）

### 界面里的外部链接必须走后端命令，不能写 `<a href>`

Tauri 的 webview **没有「新窗口」这件事**：`<a target="_blank">` 点下去既不报错也
不做任何事。用户报的原话是「主窗口左下角的小册子网站点击没有打开」—— 界面上当时
有三处这样的链接（主窗口页脚、查价悬浮窗页脚、基础配置的「访问源站」），全是点了没反应。

统一写法：`invoke("open_external_url", { url })`（Rust 侧 `rundll32 url.dll,FileProtocolHandler`
交给系统浏览器），地址常量放在 `src/lib/links.ts`。
`src-tauri/tests/frontend_conventions.rs` 里有一条自动检查守着（会先去掉注释再扫，
所以我们在注释里提「别这么写」不会误报）。

### 界面文字只留「要干什么」，不要写「为什么这样」

用户的原话：「删掉程序内的多余的解释性文字，只保留必要的功能文字说明，文字太多密密麻麻
容易看不到重点」。这一轮把整个界面按这个标准过了一遍，规律是：

| 该留 | 该删 |
| --- | --- |
| 控件名、当前值、按钮上的动作 | 背景科普（「站点每分钟探一次登录入口……」） |
| 一项操作**该怎么用**（一句就够） | 我们为什么这样设计 / 以前是什么样 |
| 出错时的原因、空结果的下一步 | 同一件事在标题、副标题、正文里说三遍 |
| 会影响判断的限定语（「不代表他干净」） | 需要用户看两行才能读完的免责声明 |

具体尺度：页面副标题一行、卡片说明一行（不超 30 字）。真要解释设计取舍，写进
本文件的对应小节或代码注释 —— 那里没人要天天看。顺手抓到的一个真 bug：
`blacklist.rs` 的 clear 结论里写了 `**本机**`，而界面按纯文本渲染 ——
用户看到的是字面上的两个星号。

## 开发约定（拦坑的自动检查）

### ⚠️ 不要在 UI 线程的回调里直接做窗口操作

Windows 上 Tauri 的窗口操作会走 `send_user_message`。如果调用发生在**主线程的回调栈里**
（同步 `#[tauri::command]`、全局热键回调、窗口/菜单/托盘事件回调、单实例插件回调），
就等于在消息处理过程中再去做窗口操作 → **重入死锁**，整个 UI 线程卡住。

这个项目已经因此出过三次事故，现象各不相同、根因完全相同：

1. 同步 `#[tauri::command]` 里 `WebviewWindowBuilder::build()`
   → 登录窗口白屏，而且点 X / 按 Esc 都关不掉；
2. 热键 / 窗口事件回调里直接 `hud.show() / hide()`；
3. 单实例插件回调里 `show() / unminimize() / set_focus()`
   → 第一个实例卡死，之后每次双击都只是多一个卡在 `SendMessage` 里的僵尸进程，
   用户看到的正是「双击后没反应」。

所以托盘、菜单、窗口这三类回调在本项目里一律只调 `reveal_window` / `hide_window` /
`close_window` / `toggle_hud_window` / `toggle_float_window` / `exit_app` 这几个
**只负责投递**的小函数（都在 `lib.rs` 里）。

**同步命令同样适用**（它们也跑在 UI 线程上）。旧版的 `toggle_hud` / `hide_hud` / `show_hud`
就直接在函数体里 `show() / hide() / set_focus()` —— **同一个风险**，只是恰好还没演成大故障。
现在它们全部改成调上面那几个投递函数，约定检查也扩到了同步命令
（`window_ops_are_not_called_directly_inside_sync_commands`）。

> 侧栏底部那个「呼出 / 收起查价窗 (Alt+F)」按钮已经**删掉**了（连同它下面的 exit 按钮一起）：
> 它显示的是程序启动那一刻读到的快捷键，而主窗口一直挂着，所以改完键它永远写着 `Alt+F` ——
> 一个看得见但会骗人的按钮比没有更糟。悬浮窗有自己的全局快捷键，设置页里还有
> 「测试呼出 / 收起」，不需要再摆一个入口。

**规矩：这些回调里只能“投递”，不能“操作”。** 窗口操作要么放进 `std::thread::spawn`，
要么写成 `async` 命令交给 tokio 跑：

```rust
.plugin(tauri_plugin_single_instance::init(|app, _argv, _cwd| {
    let app = app.clone();
    std::thread::spawn(move || {                 // ← 关键
        if let Some(window) = app.get_webview_window("main") {
            let _ = window.show();
            let _ = window.set_focus();
        }
    });
}))
```

这条约定有**可运行的检查**，`cargo test` 就会跑：

```bash
cd src-tauri && cargo test ui_thread_callbacks
```

它会扫描 `src/**/*.rs`，发现「回调闭包体或**同步命令体**内直接调用窗口操作、
且没有 `thread::spawn`」就报错（`async` 命令跑在 tokio 上，不受这条约束）。
其中 `scanner_catches_the_single_instance_deadlock` 与
`scanner_catches_window_ops_in_sync_commands` 用出事前的代码自证：这两个检查确实拦得住。

> 写这类文本级检查时注意 `async` 的位置：它写在 `fn` **之前**（`pub async fn`），
> 从 `fn` 开始截签名会把它漏掉，于是所有 async 命令都被误报成同步命令（踩过）。

### 空结果绝不进缓存

`price_cache` 是主窗口和 HUD 共用的。站点偶发地会回一个「没卡片也没报错」的页面
（乱码、被拦截、连接被截断都会长这样），一旦当成「没查到」写进缓存 5 分钟，
两个窗口就都查不到东西。所以 `query_market` 只缓存**真的有结果**的那次，
「找到 0 个匹配道具」也不会落库，界面上的「来源：实时/缓存」+「强制刷新」就是给这种情况留的出口。

### 不要用写死的假数据兜底

金价曾经在解析失败时返回一组编造的示例价格，被用户一眼看穿（真实值差十倍）。
取不到数据就**明确报错**，不要伪造。

同一条规矩也管界面上的初始值：三个窗口的内存曾经写死成 `16384MB / 7200MB / 44%`，
和真数据长得一模一样，窗口刚打开的头两秒显示的就是一个编造的占用率 —— 而这个工具本身
就是来报内存的。现在统一用 `src/lib/memory.ts` 的 `useMemorySample()`：先 `invoke` 要一次
当前采样，之后跟 `memory-update` 事件；拿不到就返回 `null`，界面显示「读取中…」。

### 界面上的失败信息不要用 `alert()` / `confirm()`

原生弹窗是另一套视觉、阻塞必须点掉、关掉就没了（用户截图过来什么都看不到），
和这个深色界面也不搭。现在统一用 `src/components/Notice.tsx`：

- 失败 / 成功信息 = 页内提示条（`InlineNotice`，可关闭、留在原地）；
- 危险操作 = 自绘确认框（`ConfirmDialog`，把要删的对象和后果写进正文，按钮上直接写动作）。

### 查询要能挡住竞态：只认最后一次响应

连着改两次关键词回车、或者「加载更多」和新搜索交叠时，两个请求同时在飞，
**先发的可能后回来** —— 结果就是「搜了 A 显示 B」。`src/lib/latest.ts` 的
`useLatestRequest()` 给每次查询发一个序号，回来时对不上就丢掉。同时 `Enter`
也要挡 `loading`（按钮有 `disabled`，但回车绕过它，连按几下就是几个并发请求打站点）。

### 换肤只改 CSS 变量，不要再硬编码颜色

深色 / 浅色两套主题**不是两套界面**：`src/index.css` 里的 `html.theme-light` 段
整组替换 Tailwind 调色板变量（`--color-slate-*`、`--color-white`、几个强调色档位），
所有用 `bg-slate-900 / text-slate-100 / border-white/10` 写出来的地方就自动跟着变。

- 它为什么可行：Tailwind v4 会把带透明度的类也编译成
  `color-mix(in oklab, var(--color-slate-900) 60%, transparent)`（包在
  `@supports (color:color-mix(...))` 里，WebView2 支持），所以连 `/60`、`/10` 这类
  也是变量驱动，而不是编译期写死的十六进制。
- **新增界面时只用调色板类**。写成 `bg-[#123456]`、`style={{ color: "#fff" }}` 就
  只有一套配色，浅色下必然出现「白底白字」。
- recharts 的 SVG 属性（`stroke` / `tick.fill`）**不认 `var()`**，图表颜色在
  `MesoTrends.tsx` 里按主题取具体值 —— 新增图表请照做。
- `white` 在浅色主题里被翻成了深色（因为本项目只用它画描边、hover 蒙层、开关滑块）；
  `text-white` 只出现在「hover 时变亮」的关闭按钮上，翻成深色正是想要的效果。
- 切换入口：`src/lib/theme.ts`（持久化 + 跨窗口同步）。主窗口右上角与 HUD 标题栏
  各有一个太阳/月亮按钮，主窗口切了，HUD 会跟着变。
- 自查办法：`pnpm build` 后打开一份「配色核对页」把两套主题各看一遗，
  重点看错误横幅（`bg-red-950/40` + `text-red-300`）和琥珀按钮（`bg-amber-500` + `text-slate-950`）。
