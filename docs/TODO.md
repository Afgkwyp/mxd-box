# 还欠着没做的事

记的是「已经知道有问题、但缺条件所以没做完」的事。做完一条删一条。

## 角色识别（0.2.0 加的）

状态栏 `LV.` 右边那两行字（职业 / 角色名），代码在 `src-tauri/src/exp/character.rs`，
位置常量在 `src-tauri/src/exp/hud.rs` 的 `JOB_TEXT` / `NAME_TEXT`。

### 1. 紧凑版状态栏下不工作

游戏窗口比较窄时会换成紧凑版状态栏（1280 宽那一套）。这套界面上职业和角色名在哪，
没有真机画面可量，所以 `HudLayout` 的 `job_text` / `name_text` 在紧凑版下是 `None` ——
角色列表不会有东西，历史也不会挂到角色上（经验统计本身不受影响）。

没有去猜坐标：框偏了把旁边的 `HP` 标签框进来，读出来的就是一个脏名字。

**怎么补**：把游戏切到会出紧凑版的分辨率（如 1280×720、1024×768），人在角色里，然后

```text
cargo test --lib -- --ignored probe_character --nocapture
DUMP_DIR=某个目录 cargo test --lib -- --ignored dump_game_frames --nocapture
```

第一条会说「没有名字 / 职业的位置」，第二条存下整幅画面；对着画面量出两行字的位置，
填进 `hud.rs`（参照宽版的 `JOB_TEXT` / `NAME_TEXT`），再用 `probe_identity_frame` 回归。
两条都要在沙箱外跑，游戏要开着。

### 2. 小分辨率下角色名可能认错首字

只在模拟里见过（把 1080p 真机画面缩到 720p–810p）：职业读得对，角色名的第一个字会认错
（`稚` 读成 `雅` / `推`）。认错的后果是同一个号在小分辨率下被当成另一个角色。

真实的小窗口是怎么渲染字的没见过，模拟不一定代表实际 —— 和上一条一样，要真机画面。

### 3. 放大的分辨率只做过模拟

1440p / 1620p / 4K 是把 1080p 真机画面放大后验的，名字和职业都读对了，但没有真机画面。
有 2K / 4K 的机器时跑一次 `probe_character` 确认。

### 4. 两个角色没法手动合并

同一个号万一被认成了两个角色（上面第 2 条那种情况），现在只能拿掉其中一个，
它名下的历史会变成「没有归属」，不能并到另一个名下。

## 地图名识别

### 5. 只在 1920×1080 窗口模式下用真机验过

0.2.0 的两个修法（先转成白底黑字、指纹只算字本身）不依赖具体分辨率，但别的分辨率、
全屏拉伸、4K 下没有实测画面。探针：

```text
DUMP_DIR=某个目录 cargo test --lib -- --ignored probe_map_name --nocapture
```

## 经验读数

### 6. 4K 显示缩放下的经验行

0.1.5 时朋友的 4K 机器（3840×2160 无边框全屏，疑似 150% 显示缩放）读不出来，
加了逐字的灰度匹配（`hudread.rs` 的 `ReadPath::Soft`），但只在模拟里验过。
真机样本会存在 `%LOCALAPPDATA%\com.mxdbox.tool\logs\经验样本\`，拿到之后做成测试素材。

### 7. 「换角色后读不出经验」的修复没有在出问题的机器上确认

0.2.0 里按代码推断修的（状态栏位置偏了却一直不重新定位）。如果还有人遇到，
要他的日志文件夹；日志里出现「看得到 EXP 标签却读不成，丢掉重新定位」说明走的是这条路。
